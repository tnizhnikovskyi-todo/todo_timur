## 07.08 — Решение открытых вопросов

**Права доступа (разбор по пунктам)**
- П.5 «Нельзя назначать неподчинённых» — **убираем кодом** (галочка ни у кого из 83 пользователей не включена, подчинённость часто меняется).
- П.12 «Нельзя менять табель в чужом проекте» — **убираем**. Остаются два важных правила: нельзя менять чужой табель; свой — только за сегодня. Удаление своего табеля разрешено.
- П.13/14 «Табели подчинённых» (видимость по оргструктуре) — **Назарию проверить**, работает ли для подчинённых.
- «Нельзя создавать контакты» без галочки — работает (галочка у двух человек, вне групп), оставляем.
- «Нельзя редактировать проекты» — нужно, но **не работает** (конфликт с «Проект: администратор»). Чинить.
- «Нельзя удалять не свои проекты» / «удалять, где не руководитель» — проверено, работает; проекты удаляет только админ (Мария).
- «Нельзя закрыть не своё задание» — неактуально, **убираем**.
- Вехи, счета, заказы на продажу (не менять/не удалять чужие) — нужны, работают.
- Финдиректору (Екатерина Ольшанская) снять админ-права в Проектах; дальше смотреть, упрётся ли она во что-то.
- Договорённость: ошибки в существующих правилах ToDo правит **за свой счёт**; принципиально новые правила — согласовываются и выставляются отдельно. Сделать подробное описание каждого правила в настройках.
- Тестовая база — бэкап 2025 г.; попросить Игоря Кутько развернуть актуальный бэкап прода.

**Элементы заказа на продажу (SO line) в задачах**
- При ручном создании задачи Odoo всегда подставляет SO line, прописанный в проекте; связи «веха → товар → SO line» нет. Поэтому при нескольких услугах в проекте часы уходят не туда (пример — проект CSM, SEO-задачи с SO line Google Ads).
- Мария настаивает: задачи вручную создавались всегда, и проблема та же, что уже решали ~3 года назад (перепривязка 7 тыс. задач).
- Решение: ТР на автоопределение SO line по вехе (согласовано Марией, без замечаний) + повторный прогон серверного скрипта выравнивания (сначала на тесте с бэкапом, потом на проде). Марии — записать видео с примерами проблемы.

**Счёт за июнь**
- Колонка «конечная дата» (в днях) — протестировано на тесте, **выкатить на прод до понедельника** (Назарий, ~0,25 ч).
- Уведомление о годовщине сотрудничества с клиентом — ТР и оценка готовы (~1,5–2 ч на ТР и оценку), отправлено Марии в Telegram.
- Мария: оплатить согласованную часть, спорные часы по SO line вынести отдельно.

## 18.08 — Доступ к БД и AI

**Конфликт по поддержке сервера (Ляховец)**
- Платят ~12 тыс. грн/год, считают, что ToDo отвечает за прод. ToDo: прод и Git (GitHub/GitLab) год назад перенесли на сторону клиента по их же инициативе; ToDo оплачивается тестовый сервер. Разговор был на повышенных тонах. Договорились: ToDo проработает варианты по зоне ответственности/поддержке и предложит их; нужна связь с сисадмином клиента.

**Запрос на AI**
- Задача — не удешевить разработку, а дать менеджерам AI-ассистента в Odoo 16 Community: чат (в идеале через Claude), который ставит задачи, отвечает по отчётам, просроченным задачам и т. п. Вариант 2 — встроенный помощник (кнопка в интерфейсе).
- Старая оценка 2025 г. (6 000 €) клиенту непонятна. Олесь: сторонние API-модули для Community стоят ~100–400 € + 5–10 ч настройки.
- Игорь: встроенный XML/JSON-RPC небезопасен; лучше MCP-сервер с ограничениями. Для поиска на естественном языке — опционально векторная копия (Qdrant + FastAPI, синхронизация раз в ночь/час). Два MCP: на чтение/аналитику и на управление.
- Упомянуто: в Odoo 19 Enterprise AI есть из коробки (но миграция дорогая).
- **Задачи:** Мария — расписать сценарии использования (вопросы менеджеров, отчёты, просрочки). ToDo — концептуальная архитектура + расчёт двух вариантов (полный и только чтение), консультация с коллегами, у которых такое уже внедрено.
