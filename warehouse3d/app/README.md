# Конструктор склада — приложение (W-01 … W-06, W-21)

Раздел «3D-модель» прототипа (`../prototype/sklad.template.html`) как отдельное приложение: ядро без DOM,
экран отдельно, хост отдельно. Данные — снимок Odoo `../prototype/data.json` (склад WH) и синтетический второй склад WH2
(`src/core/demo.js`); Odoo приложение не меняет.

## Команды (из этого каталога, нужен `npm install`)

- `npm run dev` — vite, `http://localhost:5173`.
- `npm run build` — сборка в `dist/` (относительные пути, открывается с любого адреса).
- `npm run build:odoo` — та же сборка в `../odoo_addons/wh_constructor/static/app/` (в git не попадает): её отдаёт модуль Odoo.
- `npm test` — unit-тесты ядра и словарей (`node --test test/*.test.js`).
- `npm run e2e` — Playwright против `dist/` (нужны `npm run build` и глобальный `playwright`; браузер уже установлен).
- `npm run perf` — замер плавности (`e2e/perf.mjs`, после `npm run build`): WH и синтетический склад `?synthetic=10000`; печатает время построения 3D,
  draw calls, кадр при вращении (swiftshader медленнее видеокарты), время наведения и выбора в 2D; третий замер — WH со зданием и ~1500 колоннами (здание добавляет ≤ 6 draw calls). Критерий: draw calls ≤ 200, построение ≤ 3 с, перестройка без роста числа групп.

## Структура

- `src/core/` — без DOM и без модульных переменных. `model.js` — фабрика `createModel(project, storage, opts)`
  (`opts.bases` — снимки складов по `baseRef`); `project.js` (модель проекта v2, миграции, `openProject`, `nodesOf`),
  `demo.js` (демо-проект и склад WH2), `tree.js` (снимок + слой правок + настройки склада → дерево), `layout.js`
  (раскладка в метрах), `edit.js` (diff/apply, стек несохранённых, undo/redo, операции), `select.js` (чистая логика
  выделения), `locks.js` (блокировки зон), `building.js` (план здания и проходы: геометрия, привязка, граф проходов; без состояния), `bldops.js` (операции здания через слой правок), `storage.js` (интерфейс хранения + хранилище в памяти), `types.js` (константы).
  Подписи изменений и уведомлений — данные `{ k, p }`, текст собирает i18n.
- `src/view/` — `shell.js` (оболочка), `plan2d.js`, `plan3d.js` (three.js, грузится лениво), `building3d.js` (здание в 3D), `bldplan.js` (слой здания в 2D: редактор, привязка, линейки, рулетка), `bldpanel.js` (панель режима «Будівля»), `panels.js`,
  `tools.js` (свойства, массовое создание, массив, выравнивание, группировка — разметка форм панели),  `types.js` (окно типов мест), `help.js` (инструкция), `notify.js`, `keys.js`, `style.css`.
  Каталог типов (W-05, см. ниже): `core/catalog.js`, `core/params.js`, `core/library.js`, окно типов `view/types.js` и `view/preview.js` (превью формы).
- `src/i18n/` — `uk.js`, `en.js`, `createI18n` → `t(key, params)`. Язык запоминается в `wh-app-lang`.
- `src/host/main.js` — загрузка данных, открытие проекта, монтирование view; `src/host/storage.js` — хранилище в `localStorage`
  (ключи `wh-app-*`, проект — `wh-app-project-<id>`); `src/host/odoo.js` — хранилище модуля Odoo (см. «Работа из Odoo»).
- `src/core/synthetic.js` — генератор синтетического склада (n мест, 10 рядов × 20 стелажей × 5 ярусов на зону); хост подключает его по `?synthetic=N`
  (только для проверки: проект в памяти, `localStorage` не трогается).
- 3D (D-03): одинаковые элементы (геометрия + материал + тени) — один `InstancedMesh`; `paint` решает видимость и подсветку и собирает матрицы
  (`compose`), клик/наведение — raycast по инстансам → узел, перетаскивание сдвигает матрицы. Тени пересчитываются только при изменении сцены.
  2D: SVG создаётся один раз, перестройка меняет слой содержимого, подсветка — атрибутами только у изменившихся элементов.
  Отладочные данные для perf кладутся в `window.__WH_DEBUG`, если он задан до загрузки.
- `test/` — тесты ядра на `data.json` (`core`, `project`, `i18n`); `e2e/smoke.mjs` — сценарий в браузере (включая склады, ячейки и 390 px).

## Модель проекта v2 (`core/project.js`)

- `project { schema: 2, id, name, source { kind: odoo|file|scratch, name }, loaded_at, warehouses[] }`;
  `warehouse { id, code, name, company, baseRef | base, saved, pending, building: null }`.
  Склад владеет слоем правок: `saved` (SAVED) и `pending` (PENDING); типы мест склада — `saved.types` (`null` — общий
  справочник `BASE_TYPES`, иначе свой список поверх него). `building` — сохранённый план здания (копия `saved.building`, см. «План здания»).
- Узлы склада производные: снимок Odoo + слой правок → дерево (`tree.js`) → `model.nodes()` / `nodesOf` даёт плоский
  список v2: `level` (zone, rack, bay, level, cell, floor), `tp`, `x y rot w d h`, `code`, `odoo_id` (null у новых и если
  в снимке нет id), `status` (existing, new, changed, archived), `is_location`. Корень любого склада — узел `WH` (id), подпись — код склада.
- Глубина локаций — часть слоя правок: `edit.depth` (`null` = `level` | `cell`) и `edit.depthZones [{ id зоны, d }]`; меняется
  операцией `ops.depth` через «Показати / Зберегти» с undo, как всё остальное. Ячейки яруса — `edit.cells [{ id яруса, n }]` (1–12, через «Показати / Зберегти»); при глубине `cell` и n > 1 ярус
  перестаёт быть местом, местами становятся ячейки `<код яруса>-1..n`.
- Хранилище (`core/storage.js`): `listProjects / loadProject / saveProject / deleteProject` — Promise, плюс синхронные
  настройки `read / write`. Формат версионирован (`migrateProject`). При первом запуске `openProject` создаёт демо-проект и
  переносит в склад WH правки прежних ключей (`wh-app-edit/pending`, прототип `wh-model-edit/pending`); старые ключи остаются.
  Нечитаемый проект не перезаписывается: сырая запись уходит в `wh-app-project-<id>.broken-<время>` (`backupBroken`), открывается
  демо-проект `demo-<время>`, `onNotice` → уведомление.

## План здания и проходы (W-04, D-10, D-21)

- Здание — **геометрия склада в метрах** (не локации Odoo), поле слоя правок `edit.building`: `{ v: 1, contour: [[x, y], ...], hCeil, hSpr, items: [...], nodes: [...] }`.
  `contour` — прямоугольник (4 вершины) или многоугольник; `hCeil` / `hSpr` — высота до потолка / до спринклеров. `items`: колонна `col`
  (центр, сторона), стена `wall` (отрезок, толщина), прямоугольники `gate`, `dock`, `door`, `office`, `charge` (у ворот и доков — `loc`, код локации Odoo
  или `null`), проход `aisle` (ребро графа `a`–`b` между узлами из `nodes`, ширина `w`). Узлы с одинаковыми координатами сливаются — так проходы связываются;
  конец прохода на оси другого прохода делит его (развилка). Маршрутов нет (L2–L3 — позже): ширина проходов нужна проверкам W-07.
- Через слой правок здание проходит как остальные данные: объект правки `building`, diff — общие поля (`bld`) и объекты / узлы по id (`bi`, `bn`),
  операции `model.bld.ops.*` (`bldops.js`: create, remove, contour, vertex, addVertex, delVertex, splitLongest, heights, add, grid, aisle, move, node, set, del),
  «Показати / Зберегти» (`model.save(building)`), undo / redo; числовые правки одного объекта склеиваются, сдвиг — нет. Сброс «к данным Odoo» план здания не трогает.
  Проект хранит его в `warehouse.saved.building`; `warehouse.building` — та же сохранённая копия (проекты, где здание лежало только в `building`, переносятся в слой при чтении).
- Состояние редактора — `model.bld.state` (`on`, `tool`, `grid` 0,1 / 0,5 / 1 м — запоминается как `bgrid`, `snap`, `sel`, `first`, `ruler`), событие `{ type: bld }`.
  Режим «Будівля» (кнопка рядом с 2D / 3D) показывает 2D с редактором и исключает режим «Редагувати». Рулетка (`ruler`) и точки линий — состояние редактора, не проект.
- Места внутри контура: `model.bld.outside()` — ряды и места на полу, не лежащие целиком в контуре (`rectInPoly` с невыпуклыми контурами); панель показывает предупреждение, запрет — W-07.
- 3D (`building3d.js`): непрозрачные формы — один `InstancedMesh` с цветом на экземпляр, офисы — второй, контур пола — плоскость и две линии (пол и уровень спринклеров): ≤ 5 draw calls.
- Тесты: `test/building.test.js` (геометрия, привязка, сетка колонн, граф проходов, операции через слой правок, сохранение и «перезагрузка»), шаг e2e «план будівлі…».

## Работа из Odoo (W-21, D-22)

Модуль `../odoo_addons/wh_constructor` отдаёт приложение с адреса базы (`/wh_constructor/app`, меню Склад → Конфігурація → Конструктор складу)
и добавляет в страницу `window.__WH_ODOO__ = { api, db }`. Хост по нему выбирает хранилище: есть — `createOdooStorage` (`host/odoo.js`), нет — `localStorage`.

- Интерфейс `odooStorage` тот же, что у `core/storage.js` (асинхронные `listProjects / loadProject / saveProject / deleteProject`, настройки `read / write`
  в `localStorage` с ключами `wh-odoo-<база>-*`), плюс `init` (права группами Odoo: без «проектирования» `readonly = true`), `me`, `lock`, `unlock`,
  `versions`, `restore`. Обмен — JSON-RPC (`POST /wh_constructor/api/...`, сессия Odoo); `fetch` подставляется (в unit-тестах фейковый).
- Сохранение: `saveProject(p, { commit })`. Явное «Зберегти» (`commit: true`) создаёт версию проекта на сервере (хранятся последние 50);
  черновик (несохранённое, любая правка) версий не создаёт, частые вызовы склеиваются (400 мс). Сервер хранит ревизию `rev`, клиент шлёт `base_rev`;
  если проект в базе новее — ответ `stale`, хранилище больше ничего не шлёт, уведомление «Проєкт змінено іншим користувачем» (перезагрузка страницы).
- Блокировки зон (`core/locks.js`, только если у хранилища есть `lock`): при входе в правку (выделение узла) берётся блокировка его зоны — ближайшего
  предка-группы; занята другим — уведомление `n.zoneLocked`, `edit.change` отказывает правке этой зоны, строка статуса показывает владельца и срок.
  Хост продлевает блокировки раз в минуту (`model.locks.renew`), выход из правки и закрытие страницы их снимают; срок на сервере — 5 минут.
  Блокировка берётся асинхронно: правка в первые миллисекунды после выбора зоны не блокируется.
- Проверка без Odoo: unit-тесты `test/odoo.test.js` (фейковый fetch и сервер) и шаг e2e с подменой маршрутов `/wh_constructor/api/**`.

## Каталог типов, параметры конструкции, шаблоны (W-05, D-12)

- **Каталог** (`core/catalog.js`) — 50 типов из `../build/TYPES.md` в 5 группах (стеллажные Р1–Р20 `R01…R20`, напольные `FL1…FL5`, специальные `SP1…SP8`,
  буферные зоны `BF01…BF12`, мобильные носители `MB1…MB5`): данные типа места + параметры по умолчанию + отметка «есть на мебельной фабрике» (24 / 17 / 9).
  Названия и описания: украинские — в данных каталога, английские — `cat.<код>` / `catd.<код>` в `i18n/en.js`. Тип попадает в проект (`saved.types`) вместе с первой
  постройкой (`ops.rack` / `ops.zone` с кодом каталога — одной правкой, отмена убирает и тип) или кнопкой «Додати в проєкт» (`model.types.import`); правки типа в проекте каталог не меняют.
- **3D-формы** (`params.js`, поле `shape`; `form` по-прежнему задаёт построение дерева): стойка / рулонный стелаж / штабель (сетка `gx × gy`, `h`) / зона — прежние; новые —
  ограждение / камера (`enclosure`), цилиндр / бункер (`cylinder`), шкаф-машина (`cabinet`, ярусы-лотки), мобильный носитель (`mobile`), ворота / док (`gate`). Все — инстансинг, как в W-03;
  `plan3d.js` (`structure`, `shapeLeaf`, `stackBlocks`), в 2D — условное обозначение поверх прямоугольника места (`plan2d.js`, `deco`). Вариант яруса стойки `v`: полка, балка, консоль, штанга, рельсы (уклон), соты, А-рама, вешало.
- **Параметры конструкции**: ширина / глубина секции, ярусов `lv`, высота яруса `lh` и высота каждого яруса `lhs`, нижний ярус на полу `ground`, двусторонний ряд `dbl` (секции парами спиной к спине), зазоры `gap` / `rg`, толщина
  балки `bt`, нагрузка на ярус `cap`, позиций на ярусе `pos` (= ячейки яруса W-02: у новых ярусов создаётся `edit.cells`), `deep`, `slope`, `ang`, `dia`… Схема, границы и `cleanParam` — `params.js`;
  высоты ярусов считает `levelH / levelBase / levelsTop`, их используют `layout.js` и 3D. Ряд переопределяет часть параметров (`OV_KEYS`) слоем `edit.cfg [{ id ряда, …отличия от типа }]`
  (`ops.rackcfg`, панель ряда «Конструкция ряду»; «Як у типу» — `reset`); узлы ряда видят параметры через `tree.EP(node)`.
- **Шаблоны** (`core/library.js`): `model.library.saveTemplate(id узла, имя)` сохраняет ряд или секцию (тип, ярусы и ячейки секций, переопределения, поворот); `ops.template(узел, { tpl, cnt })` вставляет —
  ряд в ближайшую зону выше узла, секцию в ряд; имена и коды новых узлов уникальны, тип шаблона, которого нет в проекте, добавляется той же правкой.
- **Библиотека** (общая для всех проектов, C10): `{ v, types, templates }`; хранилище — `listLibrary()` / `saveLibrary(lib)` (`core/storage.js` в памяти, `host/storage.js` — `localStorage`
  `wh-app-library`, `host/odoo.js` — маршруты `/library/load`, `/library/save` модуля, модель `wh.library`; при `stale` записи объединяются по `id` и запись повторяется). Хост читает её до `createModel(…, { library })`;
  `model.library` — `types / templates / saveTemplate / removeTemplate / publishType / removeType`, событие `{ type: "library" }`. Читать может «перегляд», писать — «проектування».
- Окно «Типи місць» — вкладки «Каталог» (группы, поиск, фильтр фабрики, карточка с превью и параметрами, «Додати на план»), «У проєкті» (таблица типов проекта), «Бібліотека».
- Проверка: `test/catalog.test.js` (все 50 типов создаются и дают геометрию и места, переопределения ряда, шаблоны, библиотека), `test/library.test.js` (хранилища), шаг e2e «каталог типов…».

## Инструменты редактирования (W-06, D-13)

Все операции — слой правок `edit` через «Показати / Зберегти» с undo (`core/edit.js`, `model.ops.*`). Новый слой `edit.prop [{ id, name?, w?, d?, h? }]` —
имя (только подпись, id не меняется) и собственные размеры (до поворота): у места на полу точные, у зоны — не меньше содержимого.

- **Поворот** `edit.rot [{ id, r }]`, `r` = 90 / 180 / 270 (ряд и место на полу). Узел: `rotDeg`; `rot` (меняет ширину с глубиной) — при 90 и 270, `flip`
  (порядок секций / ячеек обратный; 2D `rect2d` в `layout.js`) — при 180 и 270. `ops.rotate(ids)` — как раньше (клавиша R, 90° и обратно), `ops.rotate(ids, deg)` — заданный угол.
- **Свойства** `ops.props(id, f, key)`: имя, X / Y (от угла родителя, до сантиметра), поворот, размеры, число секций и ярусов ряда; применяются только изменившиеся поля.
- **Массовое создание** `ops.mass(зона, { tp, nr, nb, nl, gap, orient })`: ряды ставятся ниже имеющегося содержимого, проход между рядами — `gap`; `model.massInfo(f)` (`massPlan`) — сводка до «Показати».
  Массив мест на полу `ops.grid(место, { nx, ny, sx, sy })` (шаг от начала до начала; исходное место закрепляется на своём положении).
- **Рамка** `model.marquee({ x0, y0, x1, y1 }, add)` (`select.js`: `inRect`): объекты показанного уровня, целиком попавшие в рамку, того типа, что выбран в «Клік виділяє»; в 2D — Shift + протянуть, Ctrl добавляет.
- **Выравнивание / распределение** `ops.align(ids, left|right|top|bottom|cx|cy)`, `ops.distribute(ids, x|y)` — над перемещаемыми объектами (`moveTargets`), одним изменением.
- **Группировка** `ops.groupSel(ids, { name })` / `ops.ungroup(id)`: объекты переходят в новую зону (подзону) и обратно с сохранением положения и **кодов мест**. Узлы Odoo получают записи `add`
  с теми же кодами (`from` — прежний id), прежний корень попадает в `del`; в дереве `tree.js` узел, убранный и созданный заново с тем же id (возврат на прежнее место), сначала удаляется (`reborn`).
  Id узлов меняется (путь содержит родителя), коды — нет; `odoo_id` у перенесённых сохраняется (`nodesOf`), адресация и синхронизация — W-08.

## Правила

- Любое изменение поведения обновляет инструкцию (`help.*` в `src/i18n/uk.js` и `en.js`) в том же коммите;
  шаг «инструкция» в `e2e/smoke.mjs` и тест словарей это проверяют по составу, но не по смыслу.
- Тексты интерфейса — только через словарь; `test/i18n.test.js` сверяет ключи uk/en и ключи из кода.
- В `src/core` нет `document` / `window`: `grep -rnE "document|window" src/core` должно быть пусто.
