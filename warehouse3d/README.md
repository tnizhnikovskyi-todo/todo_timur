- Данные — снимок, в реальном времени не обновляются; страница только для чтения.

## Этапы

1. **Вынос блока «Склад»** в отдельную страницу без 3D: KPI, список товаров с поиском и категориями, карта мест по зонам, карточки товара и места.
2. **План 2D/3D** (нарисован с нуля, без GLB): условная раскладка склада, три.js r147 с jsDelivr, подсветка товара, фильтр «нижче мінімуму».
3. **Интерфейс как Odoo 17–19**: панель приложения «Склад», контрольная панель (хлебные крошки, поиск с фасетами, «Фільтри / Групувати за», переключатель видов, пейджер), виды список/канбан, карточки записей (smart-кнопки, группы полей, вкладки, листание ‹ ›), обзор-канбан.
4. **Внешний вид по скриншотам Odoo 19**: иконка-шестиугольник, меню с рамкой у активного пункта, бирюзовые заголовки карточек обзора, ссылки «назва — число».
5. **Меню как в Odoo 19** с выпадающими разделами. Рабочие пункты:
   - Загальний огляд → обзор;
   - Операції → Коригування залишків (остатки), Поповнення (места ниже минимума);
   - Товари → Товари;
   - Звітність → Запаси (товары списком), Розташування (список мест);
   - Налаштування → Розташування (список мест);
   - **3D** (отдельный пункт) → модель склада, стартовая страница.

   Остальные пункты Odoo (Надходження, Доставки, Партії, Упаковки, Маршрути и т. д.) показаны серыми, страниц у них нет — пока не используются.
6. **Новая модель склада (пункт «3D»)**:
   - только объекты с локацией; цех, фуры, кран, стены, колонны убраны;
   - раскладка по дереву локаций Odoo горизонтально: Вхід → Приймання → Контроль якості → Сировина → Передвиробництво → Пост-виробництво → Готова продукція → Відвантаження;
   - к уровням `complete_name` добавлены уровни из кода места: `FUR-R2-S01-L4` → Ряд R2 › Стелаж S01 › Ярус L4 (так же для `EB-U*-S*-L*`, `FG-R*-B*-L*`, `RCK-R*-<секція><ярус A–D>`, `PLT-<ряд><стос A–C>`);
   - любой уровень можно выбрать (выпадающие списки над моделью, подписи в модели, двойной клик, «↑», цепочка «Показати рівень» в правой панели) — остальное скрывается, камера приближается; работает в 2D и 3D;
   - подложка (пол) в 3D повторяет размер выбранного уровня с небольшим отступом (для яруса — размер его секции).

7. **Режим редактирования модели** (кнопка «✎ Редагувати» над моделью; пока только 3D-модель, Odoo не меняется):
   - клик в модели выбирает узел для редактирования (ярус, стелаж, ряд, зону), двойной клик показывает только его;
   - в зоне: «+ Ряд» (тип мест, число стеллажей и ярусов), «+ Місце на підлозі» (тип и количество), «+ Зона»;
   - в ряду: смена типа ряда, «+ Стелаж» (или «+ Стос» для стосов плит); в стеллаже: «+ Ярус нагорі»;
   - «Прибрати» для любого узла (вместе со всем, что внутри), «↶ Скасувати», «Скинути всі зміни»;
   - новые места синие полупрозрачные («нове · лише в моделі»), коды генерируются по образцу (`FUR-R7-S01-L1`);
   - **типы мест хранения** (кнопка «Типи місць»): код, название, конструкция (полична секція / стелаж для рулонів / палетний стелаж / стос на підлозі / місце на підлозі), ширина, глубина, высота яруса, ярусов в новом стеллаже; изменение сразу перестраивает модель, можно добавить свой тип;
   - правки хранятся отдельным слоем поверх данных Odoo: документ `model/layout` в общей базе артефакта (`types`, `add`, `del`, `set`, `pos`) — видят все, кто открывает страницу, и его можно прочитать для будущей привязки к Odoo; без базы (локальный файл) — в localStorage.
8. **Перетаскивание рядов и показ до сохранения**:
   - в режиме редактирования ряд перетаскивается мышкой в 2D и 3D (если открыт уровень, в котором он стоит); положение записывается в метрах внутри родителя (`pos`), зона расширяется под ряд; «Автоматичне положення» возвращает раскладку; при наложении на соседний ряд — предупреждение;
   - любая правка сначала только показывается в модели (бирюзовым, «не збережено»): в формах кнопки «Показати» (повторный показ той же формы заменяет предыдущий) и «Зберегти»;
   - незбережені зміни собираются по объекту, где их сделали: в панели объекта — список и «Зберегти <объект>» / «Скасувати»; сверху — «Зберегти все», «Скасувати все», «↶» (убрать последнюю); типы мест сохраняются кнопкой «Зберегти типи» в окне типов;
   - вместе с изменением сохраняются те, без которых оно не имеет смысла (новый ряд — для нового стеллажа в нём);
   - несохранённое хранится только у этого зрителя (localStorage) и переживает перезагрузку, в общую базу уходит лишь сохранённое.

## Устройство страницы (для доработки)

- Один HTML-файл, данные встроены в `<script type="application/json" id="odoo-data">`.
- `ACTIONS` — действия (виды, поиск, фильтры, группировки); `MENU` / `MENU_ITEMS` — верхнее меню; `COLS` — колонки списков; `renderForm` — карточки product / location / po.
- Модель: `codeSegs` (разбор кода места), `buildTree()` (дерево локаций Odoo + слой правок `EDIT`), `BASE_TYPES` / `TY()` (типы мест), `measure` / `place` (раскладка в метрах), `rebuildModel()` после каждой правки, `Plan` (2D-SVG и 3D-сцена, `planState.focus` — выбранный уровень, `planState.esel` — узел в редакторе).
- Редактор: `SAVED` (сохранённое) + `PENDING` (несохранённые изменения `{obj, label, diff}`) → `EDIT` (что показываем, `recompute`); `diffEdit` / `applyDiff`; `change` (показ изменения), `saveObj` / `discardObj` / `undoEdit`; `OPS` (добавление, удаление, тип ряда, `move`); `renderEditSide`, `openTypes`, `Store` (сохранение `SAVED` в базу артефакта `model/layout` или localStorage); перетаскивание — `posOverride` в `measure`, обработчики в 2D (`S2`) и 3D (`makeThree`).
- three.js грузится лениво при первом переходе в 3D: `three@0.147.0/build/three.min.js` и `examples/js/controls/OrbitControls.js` с cdn.jsdelivr.net.
