Рамки этапа: **локации и размещение**. Маршруты — следующий этап (раздел L опросника).

## 1. Цель

Универсальный конструктор склада для Odoo: подходит и для баз, где склад уже настроен (загружаем локации и
раскладываем их по плану здания), и для баз, где склад настраивают с нуля (рисуем — конструктор создаёт
локации в Odoo). Отправная точка — прототип `warehouse3d/` (артефакт «Склад меблевої фабрики»): дерево
локаций из кодов, 2D/3D, редактирование, типы мест, копирование, слой несохранённых правок.

## 3. Архитектура (предложение менеджера, к согласованию)

Ядро отделено от интерфейса и от Odoo (D-05, D-06):

- **core** — чистый JS без DOM: модель проекта, раскладка, адресация, проверки, расчёт плана изменений, сериализация.
  Покрывается unit-тестами в Node.
- **adapters** — единый интерфейс `load / diff / apply`: `odoo-api` (JSON-RPC 18/19), `file` (XLSX/CSV), позже `odoo-module`.
- **view** — 2D (SVG) и 3D (three.js, инстансинг одинаковых ячеек для D-03), панели, мастер. i18n uk/en.
- **host** — отдельное веб-приложение сейчас; модуль Odoo (OWL) — позже, на том же core и view.

Модель проекта (v2): `project → warehouses[] → building (контур, высоты, препятствия) → nodes[]`; узел: тип
(зона, ряд, секция, ярус, ячейка, напольное место), геометрия (x, y, поворот, размеры), тип конструкции,
адрес, `odoo_id`, статус (`existing` / `new` / `changed` / `archived`). Слой несохранённых правок
(`SAVED + PENDING`) из прототипа сохраняется.

## 6. Риски и вопросы менеджера

- **R-01. Доступ браузера к Odoo.** Отдельное веб-приложение не может обращаться к API Odoo напрямую из
  браузера из-за ограничений браузера на запросы к чужому домену (CORS). Варианты: небольшой
  сервер-посредник рядом с приложением; приложение, отдаваемое самим Odoo (по сути шаг к модулю);
  только файловый обмен до появления модуля. Нужно решение до W-04.
- **R-02. Где хранится проект.** До ответа на G6 — файл проекта (W-03) и хранилище браузера; общий доступ
  для нескольких людей появится вместе с выбранным хранилищем.
- **R-03. Различия Odoo 18 и 19** в полях локаций и категорий хранения — уточнить в W-04 (задача `scout`).
- **R-04. Мультисклад в первой очереди** (D-12) увеличивает W-02; заложено в оценку.

Конвенции для исполнителей: код ядра без DOM и без глобальных переменных; тексты интерфейса только через
словарь; данные Odoo только через адаптер; каждый пакет — отдельная ветка `claude/wh-<id>` и слияние после приёмки.
