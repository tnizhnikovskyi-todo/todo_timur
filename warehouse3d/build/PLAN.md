# План изменений: конструктор склада

Версия 0.2 · 2026-10-15 · основание: все 81 ответ опросника (`warehouse3d/konstruktor-opros.html`,
онлайн-версия https://claude.ai/artifact/B39oXG95VZckRsYRDg5vhe, отправлено 15.10 17:08).
Рамки: **локации и размещение**. Маршруты — следующий этап.

## 1. Цель

Универсальный конструктор склада для Odoo 18/19: для баз, где склад уже настроен (загружаем локации и
раскладываем по плану здания), и для баз, где склад настраивают с нуля (рисуем — конструктор создаёт
локации в Odoo). Отправная точка — прототип `warehouse3d/` (дерево локаций, 2D/3D, редактирование,
типы мест, копирование, слой несохранённых правок).

## 3. Архитектура

- **core** — чистый JS без DOM: модель проекта, раскладка, адресация, проверки, план изменений, сериализация. Unit-тесты в Node.
- **adapters** — интерфейс `load / diff / apply`: `file` (XLSX/CSV), `odoo-api` (18/19), `odoo-module`.
- **view** — 2D (SVG) и 3D (three.js с инстансингом для D-03), панели, мастер; i18n uk/en.
- **host** — отдельное приложение; затем модуль Odoo (OWL) на тех же core и view.
- **server** — нужен для D-19 (общие проекты, версии, блокировки, роли) и для R-01 (доступ к Odoo). Варианты — §5.

Модель проекта v2: `project → warehouses[] → building (контур, высоты, препятствия, проходы) → nodes[]`.
Узел: тип конструкции из каталога, уровень (зона, ряд, секция, ярус, ячейка, напольное место), геометрия
(x, y, поворот 0/90/180/270, размеры), адрес, `odoo_id`, статус (`existing` / `new` / `changed` / `archived`),
признак «является локацией» по настройке зоны. Слой правок `SAVED + PENDING` из прототипа сохраняется.

## 5. Нужно решить до старта этапа 4

- **R-01. Доступ к Odoo и сервер.** Отдельное веб-приложение не может обращаться к API Odoo прямо из браузера
  (браузер не пускает запросы к чужому домену). Совместная работа (D-19) тоже требует общего хранилища.
  Варианты:
  1. **Тонкий модуль Odoo** — отдаёт приложение с адреса самой базы, хранит проекты, версии и блокировки,
     даёт права через группы Odoo. Решает доступ, хранение и роли сразу; это же первый шаг к модулю из D-05.
  2. Отдельный сервер-посредник рядом с приложением (своя база проектов, свои пользователи).
  3. Только файловый обмен, без сервера — тогда D-19 и обновление по кнопке (H1) недоступны.

  Предложение менеджера — вариант 1. Этапы 1–3 от решения не зависят.
- **R-02.** Различия Odoo 18 и 19 в полях локаций, категорий хранения и правил размещения — уточнить в W-11 (`scout`).
- **R-03.** Объём: первая очередь — 20 пакетов. Темп — не больше 2 пакетов одновременно; этапы 1–3 можно начинать сразу.

## 6. Конвенции и порядок работы

- Код ядра без DOM и глобальных переменных; тексты только через словарь; данные Odoo только через адаптер.
- Каждый пакет — ветка `claude/wh-<id>`, слияние после приёмки. Состояние — `warehouse3d/build/STATUS.md` (правит менеджер).
- Реализация — агент `coder`, поиск — `scout` (`.claude/agents/`); правила экономии — `CLAUDE.md`.
