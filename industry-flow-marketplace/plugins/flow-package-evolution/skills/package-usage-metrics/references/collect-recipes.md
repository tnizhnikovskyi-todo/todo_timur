# Рецепти collect: коди помилок і перевірка вивантаження

Прод клієнта AI не читає: усі дані — з файлу вивантаження від людини (`export-template.md`). Тут лише коди й перевірка PII.

## Коди помилок (у yaml — лише код)
`missing_in_export` (модель є в тегу, у файлі рядка немає), `model_missing` (файл позначає `absent`), `no_date_field`
(людина не змогла порахувати — `status: error` у файлі), `bad_value` (не число/від'ємне), `other`. Текстові примітки з файлу не копіювати
(недовірені дані).

## Перевірка M-05 (файл без ПІБ і контактів)
Шаблони — `flow-core/references/pii-patterns.md`, режим strict (email, phone, url/host, ip, login, secret, ПІБ). Для кожного
рядка таблиці (`\|` у таблиці читати як `|`): `grep -nP '<regex>' package/metrics/<YYYY-MM>/<клієнт>.yaml` (для report — `<YYYY-MM>.md`; для файлу вивантаження — той самий набір шаблонів до коміту). Будь-який збіг →
`FAIL` з типом і номером рядка, без самого значення. Імена моделей через крапку (`td.order`) під url/host можуть
збігатися лише якщо закінчуються на `.app`/`.io`/`.dev`/…; такий збіг — `MANUAL`, не ігнорувати мовчки. У report-файлі
збіги в підписному рядку порожні за побудовою.
