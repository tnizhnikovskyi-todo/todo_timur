# REQ-ID: правила формування й дедуплікації

D-02 **не вигадує** номери. ID запиту складається з трьох частин, які вже існують у кроках-джерелах:

```
REQ-<код кроку без дефіса>-<ідентифікатор клієнта/ліда за C-05>-<ID рядка-джерела>
REQ-B02-kl07-FG-D02-03        REQ-B09-kl07-INC-012        REQ-B06-kl09-MIG-D02-01
```
Ідентифікатор клієнта — з розділу «Ідентифікатор клієнта в репозиторії» `package/DATA_POLICY.md` (приклади `kl07` — вигадані). Відкрите питання: чи допускає C-05 дефіс усередині ідентифікатора; скрипти припускають `[a-z0-9_]+`.

## Таблиця «крок -> файл -> розділ -> формат ID джерела»
| Крок | Файл | Розділ | Формат ID джерела | Стан |
|---|---|---|---|---|
| B-02 | `clients/<к>/fit-gap.md` | «Запити в D-02» | `FG-D02-NN` | визначено в плані |
| B-04 | `clients/<к>/config-log.md` | «Запити в D-02» | `CL-NNN` (пов'язаний запис журналу) | відкрите питання 3 |
| B-06 | `clients/<к>/migration-plan.md` | «Запити в D-02» | `MIG-D02-NN` | визначено в плані |
| B-09 | `clients/<к>/hypercare.md` | «Запити в D-02» | `INC-NNN` | наскрізний на клієнта |
| B-10 | `clients/<к>/support-log.md` | «Запити в D-02» | `INC-NNN` (той самий, що в hypercare) | наскрізний на клієнта |
| B-01 | `clients/<к>/sales/журнал_продажу_<к>.md` | «Запити в D-02» | не визначено (пропозиція `SAL-D02-NN`) | відкрите питання 2 |
| B-08c | `clients/<к>/acceptance-act.md` | «Запити в D-02» | не визначено (пропозиція `UAT-D02-NN`) | відкрите питання 2 |
| B-08b | артефакт UAT клієнта (шлях за шаблоном B-08b) | «Запити в D-02» | не визначено (пропозиція `UAT-D02-NN`) | відкрите питання 2 |

Якщо в рядку-джерелі є ID у форматі, не наведеному в таблиці, але він явно виданий кроком-власником (колонка «ID запиту»), його можна брати як є (скрипт `backlog_check.py` приймає `[A-Za-z0-9][A-Za-z0-9-]*`). Не з номера рядка таблиці.

## Ключ дедуплікації
Пара **(ідентифікатор клієнта, ID джерела)**, а не крок. Інцидент, перенесений з `hypercare.md` у `support-log.md` з тим самим `INC-NNN`, лишається одним запитом: REQ береться за кроком, де ID зʼявився вперше (у попередньому `backlog.md` — за наявним REQ), другий файл додається в колонку «Крок і файл-джерело» через `;`.

## Рядок без ID джерела
Не отримує REQ і номера. Потрапляє в розділ «Без ID джерела»: файл@sha, крок-власник, короткий переказ, вимога «додати колонку ID запиту». Власник файлу виправляє його сам; D-02 чужий файл не правит. У наступному запуску рядок зникає з розділу, коли в джерелі зʼявився ID.

Випадок воронки: посилання воронки має ID, але рядка з ним немає в журналі продажу. REQ не створюється; запис іде в «Без ID джерела» (шлях воронки й ID в одному рядку), власник — B-01. Що виправити: додати рядок у «Запити в D-02» журналу продажу.

## Групи GRP
`GRP-NNN` присвоюється в `backlog.md` і більше не змінюється й не перенумеровується. Один REQ належить одній групі. Групи об'єднують однакові за змістом запити різних клієнтів/лідів, але REQ-ID кожного лишається власним: `post-sign` шукає рядок-джерело саме за ним.

## Заморожені рядки
Рядок з заповненим «Рішення» (статус «рішення ухвалено» і далі) повторний запуск не змінює: ні опису, ні рекомендації, ні групи.
