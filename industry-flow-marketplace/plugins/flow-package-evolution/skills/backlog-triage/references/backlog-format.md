# Формат `package/backlog.md` (еталон шаблону `package/templates/backlog.md`)

Призначений і для `flow-package-evolution:product-decision-drafter` (D-04 бере рядки з рішенням «у продукт»). Файл варто перенести в `plugins/flow-package-evolution/references/` як спільний (відкрите питання 6, перенос робить власник плагіна). Беклог накопичувальний: один блок підпису відповідає поточному циклу, попередній підпис переноситься в журнал (див. нижче). Якщо `package/templates/backlog.md` у репо є, він первинний; цей файл — запасний еталон.

Обов'язкові заголовки (grep-контракт для D-04 і `scripts/backlog_check.py`), саме з таким текстом, рівень `##`:
`Заголовний блок`, `Запити`, `Групи`, `Причини відмов (агреговано)`, `Без ID джерела`, `Відкинуто`, `Рішення Власника продукту`, `Журнал запусків`.

```markdown
# Беклог пакета <пакет>

## Заголовний блок
- Пакет: <назва>; цільова версія: <X.Y або «не задана»>
- Режим: <а|б|в|г>; фаза: draft; дата: <YYYY-MM-DD>
- Входи (шлях@sha): <перелік усіх прочитаних>
- Маркери: <метрик немає | воронки немає | клієнтів на супроводі немає | немає>

## Запити
| ID запиту | GRP | Крок і файл-джерело | Тип | Опис (узагальнено) | Клієнт/лід | Покриття ТР галузі | Рекомендація AI (чернетка) | Рішення | Версія | Обґрунтування рішення / причина відхилення | Статус | Перший запуск |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| REQ-B09-kl07-INC-012 | GRP-001 | B-09 clients/kl07/hypercare.md@a1b2c3d (INC-012) | функція відсутня | Колір кромки має бути в специфікації виробу | kl07 (клієнт) | не знайдено | Рекомендація AI (чернетка): у продукт | | | | новий | 2026-11 |
| REQ-B09-kl07-INC-020 | GRP-003 | B-09 clients/kl07/hypercare.md@a1b2c3d (INC-020) | функція відсутня | Вбудований чат | kl07 (клієнт) | не знайдено | Рекомендація AI (чернетка): відхилити (поза пакетом) | | | | новий | 2026-11 |
| REQ-B02-kl09-FG-D02-03 | GRP-002 | B-02 clients/kl09/fit-gap.md@d4e5f6a (FG-D02-03) | функція відсутня | Обмін даними з обліковою системою клієнта | kl09 (клієнт) | не знайдено | Рекомендація AI (чернетка): у кастом клієнта | | | | новий | 2026-11 |

## Групи
| GRP | Зміст | REQ у групі | Клієнтів (на супроводі / у впровадженні) | Лідів | Використання з D-01 | Рекомендація AI | Аргумент | Що перевірити Власнику продукту |
|---|---|---|---|---|---|---|---|---|
| GRP-001 | Колір кромки в специфікації | REQ-B09-kl07-INC-012 | 1 / 0 | 0 | модель td.edge.band: метрик немає | Рекомендація AI (чернетка): у продукт | <3-5 рядків за recommendation-guide.md> | чи не окремий запит від кількох типів кромки |

| ціна | 3 | |

## Без ID джерела
| Файл@sha | Крок-власник | Переказ | Що виправити |
|---|---|---|---|

## Відкинуто
Реєстр відкинутого (формат — `flow-core/references/rejected-register.md`; 8 колонок; той самий розділ перевіряє `check_rejected.py package/backlog.md` за D-02.yaml). Окремого файла реєстру немає. Кожна рекомендація/рішення «відхилити» з «Запитів» — рядок `REJ-NNN` з її `REQ-ID` у колонці «назва». Нічого не відкинуто — рядок «нічого не відкинуто» замість таблиці.
| ID | назва | група | причина | доказ | умова повернення | де живе зараз | рішення (K1/гейт, дата) |
|---|---|---|---|---|---|---|---|
| REJ-001 | Вбудований чат (REQ-B09-kl07-INC-020) | G1 | поза пакетом: є зовнішні месенджери | гіпотеза | запит від >=3 клієнтів | немає | чернетка AI; рішення Власника — після D-02 |

## Рішення Власника продукту
Ім'я: ____  Роль: Власник продукту  Дата: ____   (заповнює людина; AI не пише)

## Журнал запусків
| Дата | Режим | Фаза | N одиниць | SHA входів | Підпис попереднього циклу |
|---|---|---|---|---|---|
```

Новий цикл: якщо попередній беклог підписано, draft дослівно переносить його підпис («ім'я, дата») у колонку «Підпис попереднього циклу» нового рядка журналу й залишає блок підпису порожнім (єдиний виняток із «AI не пише в підпис»). `post-sign` приймає лише підпис з датою не раніше за останній draft.
Статуси: `новий` (рядок створено запуском) -> `на рішенні` (draft ставить усім рядкам без рішення перед гейтом) -> `рішення ухвалено` -> `рознесено в джерело`. Статус «рішення ухвалено» ставить людина разом із рішенням; `post-sign` ставить лише «рознесено в джерело».
Клієнт/лід пишеться як `<ідентифікатор C-05> (клієнт)` або `(лід)`. Приклади вигадані (меблевий пакет); назви моделей `td.*` у прикладі ілюстративні.

Формат рядка «Запити в D-02» у файлах-джерелах — таблиця під заголовком `## Запити в D-02`; перша колонка з ID містить ID джерела, остання обов'язкова для `post-sign` колонка називається «рішення D-02 і версія пакета». Відкрите питання: точні назви колонок у шаблонах кроків-джерел; скрипти шукають колонку, що містить «рішення D-02».
