# Шлях міграції бази (крок 8, розділ «Шлях міграції бази»)

Скіл базу ядра не мігрує. Мігрує Тімлід; AI перевіряє наявність і зміст запису та лог `-u` пакета.

## Інструмент за редакцією (A-07, `docs/industries/<галузь>/business-case.md`)
| Редакція | Інструмент | Примітка |
|---|---|---|
| Enterprise | сервіс міграції Odoo (у картці — q35) | Умови доступу, строки, формат запиту — питання до Тімліда; скіл їх не вигадує |
| Community | OpenUpgrade | Чи є реліз OpenUpgrade під Odoo N — питання до Тімліда, скіл не стверджує |
| Не визначено в A-07 | — | `escalated` Тімліду, без вибору за замовчуванням |

## Що записує Тімлід
Інструмент, джерело (клас бази: лише демо-дані A-15, не копії клієнтів), стенд нової версії (alias), лог (посилання),
дата, хто виконав.

## Порядок (verify)
1. Тімлід переносить демо-базу A-15 інструментом за редакцією й піднімає стенд нової версії.
2. Тімлід заповнює розділ «Шлях міграції бази».
3. Скіл перевіряє: розділ непорожній, інструмент відповідає редакції, є посилання на лог (M-09).
4. На перенесеній базі `-u` усіх `td_*` на голову `upgrade/…`; у лозі — запуск кожного `migrations/<N>.0.X.Y/`.
5. Стан модулів — `ir.module.module` через odoo-mcp (`demo-odoo<N>`, лише читання, явний `connection_id`).

Дані клієнтів і їх знеособлені копії для цього кроку заборонені.
