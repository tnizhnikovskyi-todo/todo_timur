## R2: вихід
`research/industry-model.md` — спільна модель галузі (процеси, документи, регуляторика, ландшафт систем); `research/subsegments-deep.md` — на КОЖЕН підсегмент розділи: процеси · документи · ролі (з вакансій) · обладнання й формати · облік · оплата праці · KPI · ландшафт систем · болі з джерелами · регуляторика. Підсегмент, для якого кабінетно не вийшло, — не порожні розділи, а запис «рішення неможливе: <чого бракує, хто закриває>» + рядок у план A-23. Рецензент відкриває ці файли для пункту «кожен підсегмент — глибина або неможливо». Каркас заголовків — `industry-model.tpl.md` (шаблону ще немає — заголовки з цього абзацу). Файли мають бути в `where`/`outArtifacts` картки й `research-files` A-03b (відкрите питання власникам flow-core).

## R1: формат JSON (один запис на систему)
```json
{"id": "C-01", "name": "<назва>", "type": "specialized_erp|cad_cam|universal_erp|supplier_service|saas|substitute",
 "url": "<https://…>", "source_ids": ["SRC-001"], "evidence": "F|M|H|не перевірено",
 "segments": ["<підсегмент>"], "pricing": {"amount": null, "currency": "UAH", "fx_date": null, "conditions": "<користувачі, період, рік>"},
 "has_trial": false, "notes": "<=200 символів>"}
```
Ціни — одна валюта з курсом і датою; умови тарифів однакові. Немає даних — `null` + `не перевірено`, не вигадка. Системи без даних — короткий профіль «матриця не застосовна».

## K1: склад
1. Підсегмент першого пакета (варіанти, рекомендація, замовчування).
2. **K1-Q2** — кандидати на відкидання (замовчування «не відкидати»). У вкладену таблицю йде КОЖНА позиція, яку AI пропонує відкинути, з ID `REJ-NNN` (той самий ID потім у `REJECTED.md`; позиція без рядка в K1 у реєстр не потрапляє). Позиції за правилом класу (`do_not_reject.class_rule` анкети; типове — «є у ≥`do_not_reject.n` конкурентів або була в попередній концепції») позначаються окремо, замовчування «не відкидати». Позиції з `do_not_reject.items` AI відкидати не пропонує; бачить підставу — окреме питання-конфлікт власнику. Ліміт ≤10 стосується питань, а не рядків таблиці.
   - Відповідь власника — закритий словник: «повернути: REJ-NNN, …» (названі позиції в карту й G4а) / «повернути все» (усі в карту й G4а) / «відкинути все» (усі в G1–G3) / «за замовчуванням» = «повернути все» (у `K1.md` записується саме так). «лишити все» не вживати — двозначне. Ці варіанти вписуються в клітинку «Варіанти» K1-Q2 замість тексту шаблона. Формат розбирає `check_rejected.py`. Колонка «рішення» рядків G1–G3 у `REJECTED.md` = «K1-Q2, <дата>».
   - Повернуті в K1 позиції: у синтезі — у карту з позначкою `owner-decision` (§4.3), ризик «немає доказу попиту» — у §3.5 і план A-23, години й окупність перераховано; **у `REJECTED.md` A-03b пише для них рядки групи G4а** (посилання на відповідь K1; без цього REJ-returned = FAIL). Це показ до синтезу, а не фільтр: правило «≥2 незалежні типи джерел» — лише позначка ризику; тип доказу `owner-decision` доказовість не підвищує.
3. Прогалини джерел (група каталогу, що бракує, хто закриває). Разом ≤10 питань; надлишок — одним зведеним.
4. Відповіді власника — не кнопка: `waiting_for: {role: Власник продукту, what: "відповісти на K1-Q1…Qn"}`, `resume {k1_answers: <посилання>}`; AI вносить їх у `flow/decisions.md` лише через `flow-state-keeper` (`decisions-batch`, «внесено AI від імені власника» + посилання). Самі рішення AI не ставить. `K1.md` §4: «синтез чекає; замовчування набирає чинності лише відповіддю людини „за замовчуванням“».
5. Рекомендація AI, що суперечить анкеті, показується лише як «альтернатива» з причиною.
6. Перевірки на зупинці K1: лише `check_intake`, `check_edition_claims`, `check_privacy`; решта — після синтезу.

## Редакції
Усі твердження «CE не має X» / «EE дає X» — лише рядками `edition-claims.md` (EC-NNN). У тексті інших файлів — посилання на EC-NNN, не факт.
- CE: джерело — клон `odoo/odoo` 19.0; шлях з `inputs` наряду або preflight C-00 (назва ключа ще не зафіксована — відкрите питання власникам flow-core). Пошук — інструментом Grep за цим шляхом (агент без Bash); `git`/shell — рядками «КОМАНДИ: …» для runner. → `файл:рядок` (або GitHub `…#LN`); для «ні» — команда grep і «0 збігів» у колонці доказу. Запасний шлях без клону: GitHub `odoo/odoo`, гілка 19.0, доказ `…#LN`; «0 збігів» без клону — лише `не перевірено`. Шляху немає — вердикт `не перевірено` з причиною «клон недоступний: …» (WARN з лічильником; без причини FAIL).
- Рецензенту: фрагменти коду (±5 рядків) за ≥10 вибраними CE-рядками — у `research/review-context/EC-NNN.txt` або через «КОМАНДИ: …» runner.
- EE: URL документації 19.0 + **звірена** цитата; або запис бази EE, якщо доступ є. Доступу немає → `не перевірено` (WARN, не стоп). Відкрите питання: доступ до коду/бази EE не вирішено.
- «частково» — обов'язково «чого бракує → що добудовуємо (td_*, години)». Години мостів рахуються від вердиктів.
- `python3 -I scripts/check_edition_claims.py research/edition-claims.md --scan research/` — FAIL = повернення на виправлення; EC-scan WARN = твердження про редакції поза EC-NNN.

## Перерахунок (`params.mode: recalc`)
За `params.stale` перераховуються лише названі артефакти. Перед цим перечитати `REJECTED.md`: для кожної позиції перевірити «умову повернення» на нових фактах; виконана — запропонувати власнику зняти рішення (журнал знятих), не відкидати повторно. Після — `check_stale.py` без STALE.
