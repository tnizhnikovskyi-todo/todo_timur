# Шаблон `research/REUSE.md` (один файл, один наряд A-03c)

## Розділ `## Інвентар`
Заголовки `##` — контракт; підрозділи — `###`:
- `### Джерела` — репо/проєкти/ERP з анкети (`repo:<шлях>@<sha>`, `odoo:own-erp/ir.module.module`, `aikb:<doc_id>`), дата, клас `internal-aggregated`.
- `### Реєстр кандидатів` — таблиця:
  `| ID | Модуль | Репо@sha | Версія Odoo | Редакція | Права/ліцензія | Тести | Підтримка | Закриває F-xx | Попередня оцінка |`
  ID — `REUSE-NN` (двозначний, наскрізний; той самий ID потім у REUSE.md).
- Нуль кандидатів: замість рядків таблиці — «кандидатів не знайдено (переглянуто N репо/модулів)».
- `### Не знайдено / недоступно` — що не вдалося прочитати й чому (не вигадувати).

## Решта розділів `research/REUSE.md`
- `## Реєстр` — таблиця:
  `| ID | Модуль | Версія Odoo | Редакція | Права/ліцензія | F-xx | Рішення | Основа |`
  `Рішення` (AI) ∈ `беремо | адаптуємо | ні`; для «беремо/адаптуємо» `Основа` = `ToDo-готовий`. Годин і оцінок трудомісткості немає.
- Нуль кандидатів: `## Реєстр` — «готових модулів немає; усі F-xx — `td_` (новий)», `## Відкинуто` — «нічого не відкинуто».
- `## Вплив на карту` (необов'язковий) — які рядки `FUNCTIONAL-MAP §2.4` змінюють основу з `td_ (новий)` на `ToDo-готовий` (посилання на F-xx; сам FUNCTIONAL-MAP скіл не правит).
- `## Відкинуто` — короткий формат `flow-core/references/rejected-register.md`: `| ID (REJ-NNN) | Що не робимо | Чому | Коли повернутись |` для рішень «ні»; або рядок «нічого не відкинуто».
- `## Рішення AI` — рядки `AI-NN` для суттєвих вердиктів (формат `AI-DECISIONS.tpl.md`; ті самі рядки дописуються в `research/AI-DECISIONS.md`). Власник має вето на гейті A-20c.
- `## Відкриті питання` — зокрема ліцензія (LGPL-3 за замовчуванням, остаточно — вето власника).
