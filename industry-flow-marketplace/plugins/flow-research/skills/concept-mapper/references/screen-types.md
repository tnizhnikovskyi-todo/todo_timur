# Типи подання Odoo 19 для `screens.md`

Тип — підказка для A-21 (прототип), не рішення про реалізацію. Не писати XML, моделі, технічні імена полів.
Обирати за тим, як роль працює з об'єктом; якщо сумніваєшся — «список» + «форма».

| Тип | Коли обирати | Типові ознаки в болях |
|---|---|---|
| Список | перегляд, пошук, групування багатьох записів | «шукаємо в таблицях», «не видно, що де» |
| Форма | одна картка об'єкта з усіма полями і діями | «дані розкидані», «вводимо двічі» |
| Канбан | рух об'єктів по стадіях, видно вузькі місця | «не знаємо, на якому етапі замовлення» |
| Календар / планувальник | розклад, зайнятість ресурсів у часі | «накладки в графіку» |
| Зведення / дашборд | показники й відхилення для керівника | «звіт збираємо вручну в кінці місяця» |
| Зведена таблиця | зрізи за вимірами без коду | «щоразу просимо новий звіт» |
| Майстер (діалог) | покрокова масова дія або вибір параметрів | «довга ручна операція над багатьма рядками» |

Правила:
- Тип наводиться словами з таблиці (список, форма, канбан, календар, зведення, майстер).
- Інших типів (карта, графічні редактори, мобільні екрани) не додавати без болю в джерелі.
- Ключові поля/колонки — бізнес-назви («Дата відвантаження»), 4–8 на екран.
- Кнопки-дії — дієслова («Передати в цех»), кожна відповідає функції F-xx.
