# Шаблон `complexity.md` і критерії

Попередня оцінка функцій F-xx до обіцянки строку пілоту. Це **не** `ALLOCATION.md`: AC з'являться лише в A-08.
Годин і грошей немає. Оцінку перевіряє Архітектор рішення.

## Шапка
- Пакет, SHA входів (`FUNCTIONAL-MAP`, `BOX`, `SALES`), `build-allocator@<версія>` з `inputs` наряду, дата, `demo_edition`.
- Підсумок: стандарт — N, конфіг — N, код — N; невпевнено — N (перелік F-xx).

## Таблиця
| F-xx | Функція | Рівень CE | Рівень EE | Обґрунтування (1 рядок) | Джерело (CE: файл:рядок 19.0; EE: EC-NNN) | Впевненість | Імітація в зрізі | Примітка |
|---|---|---|---|---|---|---|---|---|
| F-01 | … | стандарт / конфіг / код | стандарт / конфіг / код / не перевірено | … | файл:рядок або URL / «немає» | висока / середня / низька | так (де) або «немає» | … |

## Критерії (витяг із «Decision rule» build-allocator; версію вказати в шапці)
Джерело правила — цей витяг. Оригінал читається лише для звірки версії: `grep -n 'Decision rule' $(find ~/.claude/plugins -path '*odoo19-mvp-build/skills/build-allocator/SKILL.md' | head -1)`
і Read ~30 рядків від заголовка. Версія build-allocator береться з `inputs` наряду (запис `build-allocator Decision rule`), не з `skill_ref`.
- **стандарт** — є з коробки Odoo 19 (рівень оцінюється **окремо для CE і EE**; ядро — CE) без налаштувань поза активацією застосунку.
- **конфіг** — досяжно UI-налаштуваннями: застосунок/модуль, налаштування, групи й права,
  шаблони листів, `base.automation` без Python, серверні дії з UI, заплановані дії, `ir.config_parameter`.
- **код** — потрібен версіонований модуль `td_*`: обчислювана/обмежувальна логіка, нова модель із поведінкою,
  контролери, нетривіальні onchange/compute, зовнішні API, власний wizard, складна state machine.
- **hybrid** (є частини обох типів) → у цій таблиці **код**, у примітці — яка частина конфіг.
- **Studio (`web_studio`) — лише Enterprise:** для рівня CE це не аргумент, у пакеті Studio не використовується (К-06/К-12); те, що вимагало б Studio, — `код` у `td_*` з приміткою. Для рівня EE Studio не пишеться як «конфіг» без вердикту `edition-claims.md`.

## Захист від заниження
- `стандарт`/`конфіг` — лише з джерелом Odoo 19 (URL офіційної документації або розділ довідника), перевіреним
  WebFetch / `boost:source-check`; для CE — також `файл:рядок` у вихідниках 19.0. Налаштування, яких не знайдено в документації, не називати.
- Немає джерела, не певен, функція не з типових → `код` і «низька».
- Впевненість: **висока** — джерело прямо описує потрібну поведінку; **середня** — джерело описує схоже, межа
  уточнюється; **низька** — джерела немає або суперечить.
- Архітектор перевіряє всі `стандарт` і всю «низьку».

## Колонка «Імітація в зрізі»
Що в зрізі є імітацією (інтерфейс є, розрахунок умовний), з посиланням на модель/екран і позначку на екрані. Функція без імітацій — «немає». Це ж перелік для README (розділ «Імітації») і для A-22.
