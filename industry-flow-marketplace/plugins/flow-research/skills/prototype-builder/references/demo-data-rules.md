# Правила демо-даних прототипу

Узгоджено з `flow-package-build/skills/demo-base-builder/references/demo-data-rules.md` (спільне ядро синтетики;
при розходженні виграє той файл, а тут робиться виправлення). Тут цифр галузі немає: діапазони беруться з
`briefing.md` і `past-projects.md`.

## Джерела діапазонів
Для кожної величини (обсяг, ціна, строк, одиниця, статус) — діапазон + посилання `<файл>§<заголовок>` у README
(розділ «Припущення даних»). Немає в джерелах → консервативне значення з позначкою «припущення»; не вгадувати.

## Синтетика
- Назви компаній, товарів, складів — з маркером «(демо)» (`Постачальник 01 (демо)`); реальних назв із ТР, брифінгу,
  past-projects, concept — немає.
- Люди — ролі (`Менеджер замовлень (демо)`), без ПІБ.
- Реєстраційні коди — `ДЕМО-0001` замість ЄДРПОУ/ІПН; IBAN немає.
- Пошта лише `*@example.com`. Телефони — лише з резервного діапазону з `package/DATA_POLICY.md`; діапазону немає →
  телефонів немає, питання в `memo`.
- Адреси вигадані («вул. Демо-Тестова, 1»).

## Seed і узгодженість
- `seed` — у `demo-data.json` і README; той самий seed → ті самі дані. Дати відносно фіксованої дати відліку, не `now()`.
- 15–40 записів на сутність; є записи в усіх станах, які показують сценарії.
- Суми = кількість × ціна (з урахуванням знижок/податків за формулою `calc`); одиниці й валюта однакові по всьому
  прототипу; дата завершення не раніше дати початку; залишки не від'ємні.

## Grep-перевірки (VP-data)
```
grep -En '[A-Za-z0-9._%+-]+@' data/demo-data.json | grep -v '@example.com'      # порожньо
grep -En '[0-9]{8,10}' data/demo-data.json                                        # немає ЄДРПОУ/ІПН-подібних (крім ДЕМО-коди)
grep -En '\+?[0-9][0-9 ()-]{8,}' data/demo-data.json                              # звірити з резервним діапазоном
grep -rFif <(реальні_назви_з_concept) data/                                        # збігів немає; список у репо не зберігати
```
Назви без «(демо)» — перевіряє `check.mjs`. Знайшлося — виправити дані, перезібрати, повторити.
