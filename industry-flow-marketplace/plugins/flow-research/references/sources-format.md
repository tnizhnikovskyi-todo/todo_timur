# Формат `docs/industries/<галузь>/_input/sources.md` (перелік джерел минулих проєктів)

Спільний для `past-projects-analyzer` (A-04), `industry-scoring`, `segment-selector`. Файл у **робочій теці `_input/`, поза git** (`.gitignore`: `docs/industries/*/_input/`); у git не потрапляє; відповідність код П-xx -> клієнт є лише тут. Заповнює людина (Власник продукту + Юрист за C-05); AI файл **не змінює** і не присвоює коди.

## Таблиця
Markdown-таблиця; перша колонка — код. Рядок заголовка обов'язковий (колонки розпізнаються за заголовком).

| код П-xx | назва клієнта/проєкту | AIKB project_id | репозиторії | Fathom recording_id | підстава обробки | режим читання |
|---|---|---|---|---|---|---|
| П-01 | Вигаданий Клієнт А | proj_example1 | odoo_addons/td_example | rec_0001 | згода/договір, пункт про AI | повний |
| П-02 | Вигаданий Клієнт Б | proj_example2 | | | немає | лише звіти |
| П-04 | Вигаданий Клієнт Г | proj_example4 | odoo_addons/td_example@build/x | | згода | повний |

## Правила
- Код — `П-\d{2}`, унікальний у файлі.
- Колонка «репозиторії»: `шлях` або `шлях@ref` (ref — гілка, тег чи SHA; кілька репозиторіїв — через `,` або `;`); допустима й окрема колонка `ref` (діє на репозиторії рядка без власного `@ref`). **Немає ref -> гілка за замовчуванням репозиторію; інша гілка читається лише за вказаним ref** (агент гілку не вибирає і з журналів збірки не виводить). ref може містити `/` (напр. `build/x`); SSH-URL з `@` (`git@github.com:org/repo`) не допускається — лише шлях або owner/repo. Другий репозиторій — `alias/шлях` (`--repo alias=<клон>`). Скрипт перевіряє (PP-ref), що `repo:<шлях>@<sha>` у документі лежить на цьому ref.
- Режим читання — `повний` (звіти, транскрипти до 3 записів на проєкт, код) або `лише звіти` (лише звіти AIKB). Режим `лише звіти` визначається наявністю підрядка «лише звіти» в будь-якій клітинці рядка.
- Немає підстави обробки -> режим `лише звіти` (правило DATA_POLICY).
- Колонки «репозиторії», «Fathom recording_id», «AIKB project_id» можуть бути порожні; значення в них — **ідентифікатори, не ПДн**; вони обов'язково з'являються в `past-projects.md` як `repo:`/`fathom:`/`aikb:` (перевірка PP-src).
- Денілист назв клієнтів для PII-перевірки — **лише колонка «назва клієнта/проєкту»** (за рядком заголовка) плюс stdin; ідентифікатори й підстава в денілист не потрапляють (`pii-patterns.md`).
- Перевірка перед запуском: файл ігнорується git (`git check-ignore -q`) і не відстежується (`git ls-files` порожній); інакше — стоп-інцидент.
- `_input/` — спільна тека галузі: поруч із `sources.md` можуть лежати вхідні файли сусідніх кроків — `README.md`, `crm.csv` (A-05). Для A-04 це не помилка; будь-який інший видимий файл або тека — PP-input. (`signals.csv`/`calls.md` A-23 тримає в `demand/_input/`.)
- Скрипт і цей формат описують одне й те саме; зміна — разом.
