# Розділи-контракти, що додаються до CONFIG.md (після шаблону config-spec)

Заголовки точні (grep-контракт). Розділи config-spec лишаються як є.

## Модулі до установки
| № | Технічна назва | Джерело | AC | Редакція |
|---|---|---|---|---|
| 1 | `stock` | стандарт | AC-01 | CE |
Порядок -- установки (топологічний). Джерело: стандарт / конфіг / готове (в складі конфіг-пакета). Редакція: CE / EE.

## Параметри установки (VP-xx)
| VP | Ключ (якір) | Трек | Ціль | AC |
|---|---|---|---|---|
| VP-02 | `ir.config_parameter:[key=sale.x]:value` | конфіг | значення за `transform` | AC-03 |
| VP-04 | `ir.config_parameter:[key=td_<пакет>.vp_04]:value` | код | реалізує модуль td_* (A-11) | AC-05 |
Кожний ключ схеми `answers.yaml` -- рівно один рядок. Deprecated -- рядок з позначкою «deprecated з версії X.Y».

## Команда установки
Версія 0.1: команди немає -- «скриптів немає; застосовано через odoo-mcp за `apply-semantics.md`; вручну -- за runbook
(`config-runbook`)». Майбутня команда -- `config-package-format.md` (CLI-контракт).

## Ручні кроки
| Пункт CONFIG | Чому не дані (секрет / інтеграція / Studio / інше) | Хто виконує | Підтвердження |
Кількість рядків іде в `memo` Тімліду.

## Зміни версії
Лише для `new-version`: змінені модулі, VP, пункти даних відносно тега `package/vX.Y` (вхід для CHANGELOG A-18).

## Відкриті питання
Пункти без AC з ALLOCATION, без джерела Odoo 19, поля/модулі, яких не знайдено в чистій базі.
