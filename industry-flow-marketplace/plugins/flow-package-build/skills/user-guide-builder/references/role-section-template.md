# Шаблон розділу інструкції ролі (`<роль>.md`)

Файл — одна роль. Ім'я файлу — латиницею (`komirnyk.md`), заголовок — українською. Не міняти формат: його читають
`check_guides.py` (UG-cover, UG-img, UG-lang) і `elearning-builder` (джерело уроків).

```markdown
# Посібник: <Роль українською>

Для кого: <1 речення>. Стенд/SHA: див. INDEX.md. Вхід у систему: демо-користувач ролі (README стенда).

## SC-01 <назва сценарію зі SPEC>
Коли: <частота: щодня / на початку зміни / раз на тиждень>.  Результат: <що має з'явитися в системі>.
Статус: готово | заблоковано дефектом D-NN

| № | Дія | Що видно |
|---|---|---|
| 1 | Відкрийте «<Меню>» і натисніть «<Кнопка>» | ![Список приймань](img/komirnyk/SC-01-1.png) |
| 2 | Заповніть «<Поле>» і натисніть «<Зберегти>» | ![Форма збережена](img/komirnyk/SC-01-2.png) |

Типові помилки: <симптом -> що робити; 1-3 рядки; тексти повідомлень системи — дослівно з `reference/messages.md` і посилання на нього>.

Питання й відповіді (FAQ):
- <Питання користувача?> — <відповідь у 1-2 реченнях; посилання на крок>.

Пов'язані AC: AC-NN.
```

Правила:
- Заголовок сценарію містить `SC-NN` зі SPEC; один сценарій SPEC = один розділ (UG-cover).
- Підписи кнопок, меню, полів — у «ялинках» і **українською, як у UI стенда**; латиниця поза `код` — FAIL UG-lang (виняток: Odoo, PDF, CSV, Excel, QR). Англійський підпис `td_*` — дефект пакета (`defects.md`, A-14); непереведений підпис стандартного Odoo — у зворотних лапках з приміткою «стандартний підпис Odoo без перекладу» (один рядок AI-NN), не дефект.
- Рядок кроку починається з `| N |` або `N.`; опис екрана — у «Що видно», зображення — `![підпис](img/<роль>/SC-NN-<крок>.png)`.
- Блоки «Типові помилки» і «Питання й відповіді (FAQ)» — явне джерело FAQ для `support-kb-builder` (A-17c) і питань тесту A-17b.
- Розділ зі `Статус: готово` має ≥1 зображення (UG-img); заблокований дефектом — без вигаданих знімків.
- Один знімок на ключовий крок; не більше 8 кроків на сценарій (довше — розбити сценарій у SPEC, не в інструкції).
- Телефони демо-контрагентів у тексті кроків не наводити (писати «телефон з картки») -- `no-pii` дає FAIL на будь-який телефон; логіни, адреси `.example` і технічні назви -- лише в зворотних лапках (інакше UG-lang FAIL за латиницю).
- Без імен реальних людей, компаній, сум, ЄДРПОУ; демо-дані стенда мають слово «Демо».
- **Права ролі (0.4.1, UG-access).** Крок називає лише меню й кнопки (зокрема смарт-кнопки), які бачить ця роль: `groups` меню/кнопки з XML ⊆ групи ролі зі стенда. Роль чогось не бачить -> дефект (`defects.md`, маршрут A-11/A-12), а не «попросіть адміністратора».
- **Кадри — під цією роллю (UG-shots).** Кадр знято, увійшовши під демо-користувачем ролі; не адміністратором, не прямим URL дії.
- **Смарт-кнопки й значки (UG-cover-buttons).** Кожна смарт-кнопка (button_box) і кнопка заголовка форми `td_*`, яку бачить роль, має бути названа в посібниках (перевіряється наявність назви; «дієслово дії + меню-шлях у рядку кроку» — вимога до автора й рецензента, а не до скрипта: перевірка рядка кроку — у 0.4.2, рішення AI-NN, власник має вето). Кнопки-значки в рядках списків (`icon=`) скрипт не перевіряє — їх покриває рецензент.
- **Шлях меню — «A» → «B» → «C»** (кожна назва у власних лапках; «A → B → C» в одній парі лапок і шлях без лапок скрипт теж розбирає); назви стандартного меню Odoo — лише з uk.po 19.0 (UG-std-label).
