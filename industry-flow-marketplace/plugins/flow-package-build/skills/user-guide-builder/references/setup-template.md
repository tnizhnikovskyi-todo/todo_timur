# Шаблон `setup.md` — «Налаштування довідників і товарів» (0.4.2, §10)

Обов'язковий файл `package/docs/user-guide/setup.md`: покрокові інструкції з налаштування й заповнення того, що пакет змінив порівняно з базовою Odoo, — **кожна стандартна форма, яку `td_*` розширив полями, і кожна модель-довідник `td_*`**. Читач — людина, що налаштовує систему з нуля (адміністратор / технолог): за цим файлом вона заводить довідники, товари й параметри без допомоги розробника. Кадри знімаються під логіном **ролі, що налаштовує** (не прямий URL дії): у `shoot-plan.json` ключ `sc` = `SETUP-NN`, файл `img/<роль>/SETUP-NN-<крок>.png`.

Перелік пунктів складає скрипт (`check_guides.py`, UG-cover-setup), а не автор: **стандартні форми** — поля `td_*` у `models/*.py` (`_inherit` стандартної моделі, без compute/related/One2many) і у `views/*.xml` (arch форми стандартної моделі); **довідники** — моделі `td.*` (не Transient/Abstract/report) з `ir.actions.act_window` і без поля `state`/`stage_id`/`status`. Поля `res.config.settings` — це `admin.md`. Модель, що лише схожа на довідник (документ, рядок, журнал), виносять у розділ «Не довідники» з причиною (≥ 3 слів); назву дії вікна цієї моделі вказують там само.

```markdown
# Налаштування довідників і товарів

Виконує <роль: адміністратор / технолог>. Порядок заповнення: <що спершу: одиниці, категорії, атрибути, потім товари, специфікації…>.

## 1. <Українська назва форми, як у UI> (`<технічна модель, напр. product.template>`)
- **Хто:** <роль, що налаштовує; група з `img/ROLE-GROUPS.json`>.
- **Де в меню:** <Застосунок → Меню → форма / вкладка>.
- **Кроки:**
  1. Відкрийте меню «…» і натисніть «Створити».
  2. Введіть … у поле `td_<поле>` (одне поле — один рядок; підписи — з UI стенда).
- **Обов'язкові поля:** `td_<поле>`, … — і де їх видно в ролі (вкладка, колонка списку, звіт), щоб перевірити результат.
- **Типова помилка:** <повідомлення системи дослівно з `reference/messages.md` або симптом> — що зробити.
- **CSV-шаблон:** `<templates/….csv або package/master-data/….csv>` для масового заповнення (імпорт «Імпортувати записи»), або `немає: <причина, ≥ 3 слів>`.

![<підпис кадру>](img/<роль>/SETUP-01-1.png)

## 2. <Довідник> (`td.<модель>`)
(ті самі шість пунктів; для довідника — усі поля форми, що обов'язкові для роботи)

## Межі налаштування
(0.4.3; розділ обов'язковий) Що **без коду не налаштувати** у конфігурованих сутностях ядра пакета: параметри виробу (напр. лише розміри Ш/В/Г), типи правил деталі (напр. лише лінійні), закритий перелік ролей матеріалів, одна формула ціни, стадії/маршрути. Джерело — рядки AI-DECISIONS «межі» (A-20) і код; кожен пункт: що можна змінити самому, що вимагає доробки (беклог / REQ-ID) і де про це домовлено. Власник має дізнатися про межі з цього розділу, а не на показі.

## Не довідники
| Модель | Чому не довідник |
|---|---|
| `td.<модель>` (дія «<назва>») | <причина: документ зі станом / рядок документа / журнал> |
```
Правила перевірки (UG-cover-setup): заголовок розділу містить технічну модель у зворотних лапках; кожне поле `td_*` цієї моделі названо в тілі розділу (технічне ім'я в зворотних лапках); у розділі є пункти «Хто», «Де в меню», «Кроки», «Обов'язкові поля», «Типова помилка», «CSV-шаблон» і ≥ 1 кадр; шлях CSV існує; у INDEX є таблиця «## Покриття: налаштування довідників» з кожною моделлю. Рядок таблиці з позначкою «описано в цьому рядку» покриттям **не є** (так само таблиця «Поля пакета на стандартних формах» у `admin.md`).
