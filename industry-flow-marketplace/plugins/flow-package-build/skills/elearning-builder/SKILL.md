# eLearning Builder — електронне навчання в збірці пакета (A-17b)

## Мета
Покласти навчання **всередину пакета**: після установки на чисту Odoo 19 CE користувач знаходить у розділі eLearning курс
своєї ролі, проходить уроки (ті самі тексти й знімки, що в інструкціях A-16b) і складає тест з оцінкою. Клієнт отримує це
готовим; `user-training-builder` (B-07) лише адаптує під його конфіг. Модуль — звичайний `td_*` пакета, тому на ньому діють
гейти A-14 і релізні правила A-18.

## Наряд і звіт
Вхід — наряд (`flow-core/references/naryad-format.md`), читає `flow-core:flow-step-runner`; профіль доступу `repo` + тестова база
(alias з `odoo_connections`, **кожен виклик з явним `connection_id`**; `flow`, прод, демо, база клієнта — не для запису). Виконавець AI,
рецензія — Тімлід/контент-менеджер. Результат — файли за `where` (`package/addons/td_<галузь>_elearning/`); звіт і PR пише runner,
скіл повертає дані для `checks`, `data_sources`, `memo`. Ліміти — з картки кроку.

## Що чиє
| Що | Чий крок | Тут? |
|---|---|---|
| Тексти й знімки інструкцій | A-16b `user-guide-builder` | ні, лише читається (джерело уроків) |
| Модуль `td_<галузь>_elearning`, data XML, тести | цей крок | так |
| Рев'ю коду/безпеки модуля | A-14 `gates-aggregator` (pr-review, security-review) | ні |
| KB для AI-підтримки | A-17c `support-kb-builder` | ні |
| Адаптація курсів під клієнта | B-07 `user-training-builder` (зовнішній) | ні |
| Включення в реліз | A-18 `package-release-builder` | ні |

## Входи
`package/docs/user-guide/INDEX.md` і `<роль>.md` (A-16b, SHA стенда), `package/SPEC.md` (AC для питань), `package/ALLOCATION.md`
(модуль `td_<галузь>_elearning` не потребує згадки в ALLOCATION, але depends/редакції звірити), `answers.yaml` (`elearning.mode`,
`elearning.pass_score`), `OWNER-INTAKE.md` (`editions`), `research/AI-DECISIONS.md` (куди писати рішення й ризики), вихідники Odoo 19.0.

## Крок 1. Звірка з вихідниками 19.0 (до написання XML)
Твердження про Odoo 19 — **не факт, а перевірка**. За `references/source-verification.md` для кожного пункту знайти файл:рядок у
вихідниках `19.0` (GitHub odoo/odoo, гілка 19.0; Grep по `addons/website_slides`, 50–100 рядків навколо збігу) і записати його в
`README.md` модуля та в `memo`: моделі `slide.channel`, `slide.slide`, `slide.question`, `slide.answer`; назви обов'язкових полів і
типів уроку; де задається підсумок/бали тесту; чи є (і де) поріг проходження; чи є `website_slides_survey` у ядрі CE 19.0 і
що саме він дає для сертифікації. Не підтверджене -> поле/можливість не використовується; у `research/AI-DECISIONS.md` рядок
«перевірити у вихідниках 19.0: <що>» з ризиком. Сертифікація без підтвердження `website_slides_survey` — **не робиться**, запис «не перевірено».
Підтверджені імена полів скрипт приймає через `--schema` (скрипт містить чернетку констант — `scripts/check_elearning.py`, `SCHEMA`).

## Крок 2. Курси й уроки
1. Ролі = файли `<роль>.md` у user-guide (разом з `admin.md`) -> **один курс на роль**; у XML-коментарі всередині `<record>` курсу — `role: <роль>`.
2. Урок = розділ `## SC-NN` посібника ролі; у коментарі запису уроку — `source: <роль>.md#SC-NN`. Текст кроків і знімки переносяться
   як є (картинки — з `package/docs/user-guide/img/`, копії в `static/img/` модуля чи вкладення data XML — спосіб за `references/module-structure.md`);
   текст не переписується — розбіжність із A-16b = дефект (EL-source).
3. Українською: назви курсів, уроків, питань і відповідей (EL-lang).

## Крок 3. Тести з оцінкою
Після останнього уроку кожного курсу — урок-тест (`slide.slide` з питаннями). Мінімум 5 питань на курс; у кожного питання ≥2
варіанти й **рівно одна** правильна відповідь (багатовідповідне — лише з коментарем `multi: true` і поясненням у `memo`). Питання —
з AC і кроків сценаріїв ролі (за `references/lesson-mapping.md`): що робити, де видно результат, що робити при помилці; не «на пам'ять»
про технічні назви. Поріг проходження — параметр `ir.config_parameter` `td_<галузь>_elearning.pass_score` (значення з `answers.yaml`
`elearning.pass_score`, за замовчуванням 80), як він застосовується в тесті — за вихідниками 19.0 (Крок 1); якщо штатного порога немає —
«не перевірено» і рядок у AI-DECISIONS, поріг лишається параметром для звіту, а не вигаданим механізмом.

## Крок 4. Параметр пакета `elearning: on|off`
`answers.yaml` ключ `elearning` (`on` за замовчуванням); у модулі — `ir.config_parameter` `td_<галузь>_elearning.mode` зі значенням `on|off`.
`off` — курси не публікуються/не видні користувачам (механізм — за вихідниками 19.0; без підтвердження — запис «не перевірено»).
Ключ додається в `questionnaire.md`/`answers.yaml` рішенням A-09 (`questionnaire-builder`) — тут лише повідомлення в `memo`, файли A-09 не змінюються.

## Крок 5. Модуль і тести
Структура й приклад data XML/тесту — `references/module-structure.md`, `references/course-data-example.xml`, `references/test-example.py`.
Тести модуля (`tests/`): установка на чистій CE; кількість курсів = кількість ролей; у кожного курсу ≥5 питань. Прогін —
`run_tests.sh <db> /td_<галузь>_elearning:<TestClass>` (скрипти C-00); немає бази/скрипта -> `EL-install` = SKIPPED = не готово.
Перед «готово» — `boost:odoo19-lint` по модулю.

## Запис
Лише `package/addons/td_<галузь>_elearning/` (`__manifest__.py`, `data/*.xml`, `static/`, `tests/`, `README.md`) і рядки `research/AI-DECISIONS.md`
(рішення AI з ризиками). Не змінювати інші модулі, `package/docs/user-guide/`, `answers.yaml`.

## Автоперевірка
`python3 -I scripts/check_elearning.py --module package/addons/td_<галузь>_elearning --guide package/docs/user-guide [--pass-score N] [--schema schema.json]`
(stdlib; JSON `[{id,status,msg}]`; код 1 = є FAIL).

| ID | Перевірка | FAIL, коли |
|---|---|---|
| EL-courses | курс на кожну роль з user-guide (маркер `role:`), кількість курсів = ролей | немає курсу ролі / зайвий |
| EL-quiz | на курс ≥5 питань, ≥2 відповіді, рівно одна правильна (крім `multi: true`) | менше або інакше |
| EL-source | кожен урок (не тест) має `source: <файл>.md#SC-NN`, файл і розділ існують | немає посилання / розділу |
| EL-lang | назви й тексти курсів, уроків, питань українські (без латиниці поза білим списком) | латиниця |
| EL-pass | параметр `*.pass_score` є, 1..100, = `answers.yaml` (за замовчуванням 80) | немає / не збігається |
| EL-mode | параметр `elearning` має значення `on` або `off` | немає |
| EL-deps | `depends` містить `website_slides` (і `website_slides_survey`, якщо є survey-записи) | немає |
| EL-tests | `tests/` має test_*.py, що звертаються до курсів і питань | немає |
| EL-install, EL-cert, EL-schema | MANUAL: установка на чистій CE і тести (SKIPPED = не готово); сертифікація підтверджена файл:рядок або «не перевірено»; імена зі схеми звірено з 19.0 | агент |

**Готово, коли:** EL-* без FAIL; EL-install виконано на чистій CE; кожен пункт Кроку 1 має файл:рядок або запис «не перевірено» в AI-DECISIONS; lint чистий.
Редакції: EE-частина (якщо потрібна) — «не перевірено» без EE; не видавати за PASS.

## Дані для звіту
`checks` — рядки таблиці; `data_sources` — `repo:<шлях>@<sha>` входів, `odoo-src:19.0:<файл>:<рядок>` для кожної звірки; `memo`: «Невпевнений:»
(поріг/сертифікація/`off`), «Що змінилось:», «Де ризик:», «Що перевірити:».

## Pre-save верифікація
- [ ] Курсів = ролей user-guide; кожен курс має тест ≥5 питань, у кожного питання рівно одна правильна відповідь
- [ ] Кожен урок має `source:` на існуючий розділ; тексти не відрізняються від A-16b
- [ ] Імена моделей/полів звірено з вихідниками 19.0 (файл:рядок у README модуля); непідтверджене не використано
- [ ] Сертифікація — лише при підтвердженому `website_slides_survey`, інакше «не перевірено» в AI-DECISIONS
- [ ] `pass_score` з `answers.yaml`/80; `elearning` on|off; є `tests/`; `boost:odoo19-lint` без помилок
- [ ] Немає даних клієнтів; змінено лише модуль і AI-DECISIONS; бінарників баз немає

## Наступний крок
«Електронне навчання A-17b готове» -> A-18 (AND-join з A-17c; `package-release-builder` включає модуль у реліз). Дефект у user-guide -> A-16b;
дефект модуля/гейтів -> A-14.

## Чого НЕ робити
- Не вигадувати моделі, поля, виклики API й поведінку website_slides чи website_slides_survey як факт — лише «перевірити у вихідниках 19.0, файл:рядок».
- Не включати сертифікацію без підтвердження; не писати про вартість/ціну навчання.
- Не переписувати тексти уроків (джерело — A-16b); не змінювати user-guide, answers.yaml, інші модулі.
- Не писати в бази поза тестовою з allow-list; не викликати odoo-mcp без `connection_id`.
- Не робити питання з кількома правильними без `multi: true`; не робити тести без пов'язаних AC/кроків.
- Не писати звіт у задачу Odoo й не відкривати PR — це робить `flow-step-runner`.

## Відкриті питання
- Штатний поріг проходження тесту в `website_slides` 19.0 і спосіб застосувати `pass_score` — з вихідників (Крок 1), рішення Архітектора.
- Спосіб приховати курси при `elearning: off` (група, публікація, видалення даних) — вихідники 19.0.
- Ключ `elearning` в `questionnaire.md`/`answers.yaml` — рішення A-09 (`questionnaire-builder`).
- Зображення уроків: `static/` чи вкладення — за практикою `td_*` пакета (A-11, `module-skeleton`).
