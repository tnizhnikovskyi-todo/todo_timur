# Контракт CI (C-00 / C-03) для A-18

Статус: скрипти C-00 і workflow C-03 ще не існують (відкрите питання). Нижче — вимоги скіла до них, не факти про наявні файли.

## Входи `workflow_dispatch` (очікувані)
| Вхід | Значення |
|---|---|
| `ref` | HEAD гілки `release/<тег>` |
| `tag_candidate` | `package/...` |
| `mode` | `install` / `upgrade` |
| `prev_tag` | попередній тег (для `upgrade`) |
| `instance` | ідентифікатор інстанса з бронювання (для `upgrade`) |

## Що вважається «однією командою»
Одна команда скрипта C-00 із тегом/ref як аргументом, що розгортає чисту базу Odoo 19, ставить усі модулі пакета, застосовує
конфіг, імпортує шаблони майстер-даних і завершується кодом 0. Кілька ручних кроків — FAIL R-09 «не одна команда».

## Smoke
Скрипт C-00 після установки; вміст визначає C-00. Скіл не придумує перевірок.

## Результат
`actions_get`: статус, `head_sha`; `get_job_logs` — лише `ERROR|CRITICAL|Traceback` (<= 30 рядків). У CHANGELOG: id інстанса,
SHA прогону, витяг.

## Режим «вручну» (поки скриптів немає)
У `memo` дати людині точні команди за шаблоном: (1) чиста база Odoo 19, (2) установка пакета за тегом-кандидатом,
(3) smoke, (4) для оновлення: підйом `PREV` з демо-даними на окремому інстансі, `-u` до HEAD, smoke. Статус R-09...R-11 —
`NOT_RUN` до логу від людини; done не заявляти. Конкретні назви скриптів — відкрите питання до AI-інженера/Тімліда.
