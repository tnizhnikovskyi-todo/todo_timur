# Формат package/demo/release-defects.md

Файл створює A-18 при дефекті пакета; читає `gates-aggregator` (режим `повернення`, джерело A-18).
Узгоджено з `gates-aggregator/references/return-routing.md`.

## Таблиця
| Версія | Спроба | Тип | Витяг з логу (<= 30 рядків) | SHA | Код повернення | Цільовий крок |
|---|---|---|---|---|---|---|
| `package/v1.2` | 1 | версія | `version 19.0.1.1 != ACCEPTANCE 1.2` | `<sha>` | A-14 | A-11 |

Один дефект — один рядок. Лог — у блоці під таблицею з якорем `RD-<n>`, без даних клієнтів і ПІБ.

## Тип -> цільовий крок
| Тип | Приклади | Цільовий |
|---|---|---|
| модуль | установка/оновлення/smoke падає в td_*; lint FAIL; зміна моделі без міграції; вендорений без ліцензії/джерела; комплект ≠ ACCEPTANCE | A-11 |
| конфіг | помилка встановлення конфігу в чистій базі | A-12 |
| майстер-дані | помилка імпорту, дані клієнта в майстер-даних | A-13 |
| анкета | deprecated без інструкції, VP без default | A-09 |
| версія | X.Y тега/ACCEPTANCE/version td_* розходяться | A-11 |
| diff | зміни поза дозволеним списком (файли названо) | за шляхом файлу: addons -> A-11, config -> A-12, master-data -> A-13 |

Код повернення завжди A-14 (контур), цільовий крок — підказка для `gates-aggregator`; код визначити неможливо —
ескалація, не «?». Нестача передумов (немає підпису, немає інстанса) у цей файл не пишеться.
