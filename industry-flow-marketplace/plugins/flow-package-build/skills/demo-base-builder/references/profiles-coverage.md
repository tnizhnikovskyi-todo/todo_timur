# Профілі answers.yaml і покриття VP-xx (A-15, №40)

## Вхід
`package/questionnaire.md` (перелік VP-xx), схема `package/templates/answers.yaml` (допустимі значення, залежності, deprecated),
`answers.example.yaml`. Якщо схема не описує допустимі значення якоїсь VP-xx — це відкрите питання до A-09 (в `memo`), не вгадувати.

## Алгоритм
1. Таблиця: VP-xx → множина допустимих значень (зі схеми).
2. Покриті значення = значення з `answers.example.yaml` ∪ `answers.yaml` (базовий — копія example з демо-значеннями).
3. Жадібно: взяти непокрите значення, створити `profiles/answers.alt-<N>.yaml` = базовий + зміна цього значення, плюс найбільше
   інших ще непокритих значень, якщо вони незалежні. Повторювати, поки непокритого немає. Мета — мінімум профілів.
4. Залежні VP-xx (якщо схема їх задає) — лише в сумісних комбінаціях; несумісні значення — окремі профілі.
5. Валідація кожного файлу: ключ для кожної VP-xx, значення з допустимих, deprecated не використано, зайвих ключів немає.
6. Кожен профіль встановлюється на окремому інстансі `<instance>-p<N>` (`up.sh --profile`); час установки всіх профілів не
   вкладається в `timeoutMin` → не пропускати, а питання Тімліду (матриця C-03, В-2).

## Таблиця покриття для README
| VP-xx | значення | де покрито (example / answers / alt-N) | профіль встановлено (так/ні/причина) |
Порожніх клітинок «де покрито» бути не має; профіль, що не встановився, — дефект (тип за `defects-format.md`).
