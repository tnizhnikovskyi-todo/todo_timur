# Код повернення правки

## Правило: за шляхом файлу знахідки, не за гейтом
| Шлях знахідки | Код |
|---|---|
| `package/addons/**` | A-11 |
| `package/config/**`, `package/config/CONFIG.md` | A-12 |
| `package/master-data/**` | A-13 |
| у режимі `hotfix` — будь-який з вище | A-19 |

Знахідка без шляху — за гейтом: pr-review / security-review / odoo19-lint (код) -> A-11;
config-review -> A-12; тест-імпорт -> A-13. Позначити в `memo` «маршрут за гейтом, а не за шляхом».
Дефект, що ламає і код, і конфіг (hybrid-AC) — дві правки з різними кодами, обидві із посиланням на дефект.
Червоний C-03 — код за шляхом тесту, що впав (зазвичай A-11).
Код визначити неможливо — правка з кодом «?» заборонена: ескалація Архітектору з цитатою знахідки.

## Артефакти повернення (режим `повернення`)
| Джерело | Артефакт | Поле -> код |
|---|---|---|
| A-15 | `package/demo/defects.md` | помилка установки конфігу / VP-параметр -> A-12; помилка модуля, міграції, прав -> A-11; невалідний рядок/порядок імпорту CSV -> A-13 |
| A-16 | `package/demo/scenarios.md` | непройдений сценарій з маршрутом A-14: код за полем «причина» (код/конфіг/дані) |
| A-17 | `package/ACCEPTANCE.md` | відхилений AC з кодом A-14: код за типом AC з ALLOCATION (code -> A-11, config -> A-12, hybrid -> обидва) |
| A-18 | `package/demo/release-defects.md` | помилка установки за тегом: за шляхом/типом дефекту |
Точна структура цих артефактів визначається скілами їхніх кроків; якщо поле з причиною порожнє — не вгадувати,
а ескалація (код «?»). Дефект переноситься як правка з посиланням на джерело (крок + ID); кількість правок
має збігатися з кількістю дефектів. ПІБ/контакти з дефектів у CHECKS.md не переносити.

## Неоднозначні випадки -> ескалація
- Знахідка вказує на файл поза `package/addons|config|master-data` (напр. `ci.yml`) — не наша зона: ескалація.
- Дефект описано без файлу й без типу («не працює») — ескалація з цитатою.
- Помилка установки, причина якої може бути і в конфігу, і в моделі — дві правки (A-11 і A-12), `memo` пояснює.
