# Протокол гейтів A-14

## Порядок і залежності
1. `odoo19-mvp-build:pr-review` — весь `package/addons/` (td_* і вендоровані «готове») проти `package/SPEC.md`.
2. `odoo19-mvp-build:security-review` — той самий обсяг; у A-14 запускається завжди, навіть при правках
   pr-review (позначка «запущено до APPROVE pr-review — режим A-14»). Відкрите питання В-4: наявний скіл
   очікує APPROVE pr-review. При pr-review ≠ APPROVE — виклик з параметром «режим A-14: pr-review = <вердикт>, аудит незалежно»;
   відмова скіла → «не виконано: очікує APPROVE pr-review (В-4)» — штатний вердикт (не збій, не APPROVE), `memo`.
3. `odoo19-mvp-build:config-review` — `package/config/` + `CONFIG.md` проти ALLOCATION і шаблонів A-13.
4. `boost:odoo19-lint` — `package/addons/` і `package/config/`.
5. `odoo19-mvp-build:track-convergence` + тест-імпорт `package/master-data/` — лише якщо pr-review = APPROVE
   і config-review = APPROVE (у версії 1 ще й конфіг застосовано Тімлідом). Інакше «не виконано: …» — штатно.

## Нормалізація вердиктів
| Результат гейту | У CHECKS.md | Примітка |
|---|---|---|
| APPROVE | APPROVE | |
| REQUEST CHANGES | правки | знахідки з `файл:рядок` -> правки F-nn |
| BLOCK | правки | позначка серйозності BLOCK зберігається |
| odoo19-lint: 0 знахідок | APPROVE | |
| odoo19-lint: >=1 знахідка | правки | |
| Немає вердикту / не відпрацював / не те підключення | збій виконання | одна повторна спроба; лічиться в `maxAttempts`; ніколи не APPROVE і не «правки» |
| Умова не виконана (track-convergence/тест-імпорт; security-review — лише В-4 при pr-review ≠ APPROVE; track-convergence — В-6 з `result: escalated`) | не виконано: <причина> | не збій |
| Вердикт перенесено | перенесено з <SHA> | див. нижче |

Підсумок кроку виводиться з таблиці механічно: APPROVE лише якщо всі п'ять гейтів APPROVE.

## Перенесення вердикту (лише режим `перевірка`)
Попередній CHECKS.md з SHA гейтів `P`. Для кожного обсягу:
- `git diff --quiet P HEAD -- package/addons/` -> вердикти pr-review, security-review і lint-частини addons
  переносяться з позначкою «перенесено з P».
- `git diff --quiet P HEAD -- package/config/` (і `CONFIG.md`) -> те саме для config-review і lint-частини config.
- Переносяться лише вердикти APPROVE або відкриті правки з попереднього циклу; «збій виконання» не переноситься.
- `track-convergence` і тест-імпорт перезапускаються завжди, якщо змінилось будь-що в
  `package/addons|config|master-data`.
- Режими `нова-версія` і `hotfix`: нічого не переноситься. Режим `повернення`: гейти не запускаються взагалі, а всі п'ять рядків таблиці — «перенесено з <SHA попереднього CHECKS.md> (режим повернення, не перезапускались)».

## Режим пакета для track-convergence
Наявний скіл пише `сходження-треків_[компанія].md` і чекає план міграції клієнта (відкрите питання В-6).
У A-14 скіл викликається з явними параметрами: scope — пакет; база — `test-pkg-<пакет>` з allow-list наряду;
майстер-дані — шаблони `package/master-data/`; план міграції клієнта не потрібен. Результат (`сходження-треків_*`) не в репо — лише scratchpad; замість плану міграції — `package/master-data/README.md`; витягти вердикт і знахідки в «Деталі гейтів» CHECKS.md. Чи охоплює
track-convergence CSV-шаблони — невідомо (В-1): покриття CSV перевіряється окремо.

## Структура CHECKS.md
Єдина структура — `plugins/flow-package-build/references/checks-template.md` (не дублювати; тут лише доповнення: колонки «перенесено з SHA», «знахідок», покриття ALLOCATION, матричний тест №40, «Конфіг застосовано» у версії 1, лічильник циклів).
- Шапка: пакет, режим, версія флоу (1/2), спроба, цикл N з 3, дата.
- SHA гейтів (HEAD package/ на момент запуску); SHA прогону C-03, run id, статус, «предок без змін у addons/config: так/ні».
- Конфіг застосовано (версія 1): база (alias), дата, хто, VP-xx = значення.
- Таблиця гейтів: гейт | скіл@версія | обсяг | вердикт | перенесено з SHA | знахідок (BLOCK/інші).
- Покриття ALLOCATION: модуль/файл | тип (td_*/вендорений/конфіг/CSV) | яким гейтом покрито.
- Матричний тест №40: VP-xx | значення | профіль | результат.
- Правки: F-nn | джерело (гейт або A-15..A-18 + ID) | файл:рядок | опис | серйозність | код повернення | статус.
- Підсумок: APPROVE | правки -> {A-11, A-12, A-13} | ЧАСТКОВО (очікує підкрок) | ескалація.
- Деталі гейтів: стислий витяг знахідок (без повних звітів; чи зберігати повні — В-5).
