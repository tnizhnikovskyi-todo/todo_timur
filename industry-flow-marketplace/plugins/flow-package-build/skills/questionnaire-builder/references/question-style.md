# Мова питань анкети

Читач — керівник чи фахівець підприємства, не адміністратор Odoo. Питання про його процес, а не про систему.

## Правила
1. Одне питання — одна VP-xx. Не склеювати два параметри в «і/або».
2. Без термінів Odoo. Стоп-слова: «модуль», «поле», «маршрут», «Inventory», «Manufacturing», `res.`, `td_`,
   `x_`, назви меню/пунктів інтерфейсу, MTO/MTS/BoM без розшифровки. Дозволено галузеві слова клієнта
   (замовлення, склад, цех, специфікація виробу).
3. Закритий список: 2 і більше варіантів, кожен -> рівно одне значення `allowed`; відкрита відповідь («опишіть»)
   заборонена. Для `bool` — «Так» / «Ні»; для `int` (немає `allowed`) — закрита шкала: число з діапазону `min..max` ТР. Якщо ТР не дає варіантів — це дефект ТР (`tr-defect: no-variants`), а не вільний текст.
4. Останній варіант завжди «Не знаю / потрібна консультація». Це не значення VP: B-02 перетворює його на `уточнити`.
5. Варіант пишеться так, щоб клієнт міг його обрати без пояснень; якщо потрібне пояснення — одне речення в дужках.
6. Під-питання (те саме VP) дозволене лише з `applies_if` і позначкою «уточнення до Q-NN»; без цього дубль = FAIL `vp-dup`.
7. Не підказувати «правильну» відповідь і не згадувати default.

## Погано / добре
| Погано | Добре |
|---|---|
| Який маршрут поповнення використовувати? | Ви виготовляєте вироби під конкретне замовлення чи на склад? |
| Вкажіть значення поля «Тип виробництва» | Яким способом ви більшість виробів запускаєте у виробництво? |
| Чи потрібен модуль обліку плитних матеріалів? | Чи ведете ви облік залишків плит і обрізків? |
| Опишіть вашу складську структуру | Скільки складів ви використовуєте (від 1 до 5)? |
| Чи вмикати MTO? | Чи запускаєте ви виробництво лише після підтвердження замовлення клієнтом? |
| Які типи BoM у вас? | Які типи виробів ви випускаєте: корпусні, кухні, офісні? (оберіть усі, що підходять) |
| Налаштувати res.users.groups для цеху? | Чи має майстер цеху самостійно підтверджувати завершення операцій? |
| Чи актуально для вас? (без контексту) | Це питання лише для змішаного виробництва: <питання> |
Приклади вигадані, лише ілюструють тон; реальні формулювання береться з ТР.

## Зразки по типах (колонки «Варіанти відповіді» і «Значення VP по варіантах»)
| Тип | Варіанти відповіді | Значення VP по варіантах | «Не знаю» |
|---|---|---|---|
| `enum` | 1. під замовлення 2. на склад 3. Не знаю / потрібна консультація | 1 -> make_to_order; 2 -> make_to_stock; 3 -> (уточнити) | так, останнім |
| `multi` | 1. корпусні 2. кухні 3. офісні 4. Не знаю / потрібна консультація (оберіть усі, що підходять) | 1 -> cabinet; 2 -> kitchen; 3 -> office; 4 -> (уточнити) | так, останнім |
| `bool` | 1. Так 2. Ні 3. Не знаю / потрібна консультація | 1 -> true; 2 -> false; 3 -> (уточнити) | так, останнім |
| `int` | число від 1 до 5; або Не знаю / потрібна консультація | число -> те саме число; Не знаю -> (уточнити) | так: окремий варіант поруч зі шкалою |
Вимога «>=2 варіантів 1:1» для `int` виконується шкалою `min..max` (два й більше допустимих чисел) плюс «Не знаю».
