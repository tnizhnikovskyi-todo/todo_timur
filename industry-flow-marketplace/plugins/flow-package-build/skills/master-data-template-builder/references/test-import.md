# Тест-імпорт шаблонів у чисту тестову базу

Мета - довести, що стандартні файли `package/master-data/NN_*.csv` імпортуються без помилок. Файли з `td/` не імпортуються
(потрібні модулі A-11). Запис - лише в **чисту тестову базу пакета** з allow-list наряду (у `gates-aggregator` вона має
alias `test-pkg-<id>`; остаточний клас - відкрите питання до C-00/C-05). У базу `flow`, прод і демо - ніколи. Видалень немає.

## Спосіб 1 (основний): скрипт C-00 «імпорт шаблонів»
Контракт (скрипта в `tools/odoo/` ще немає, не посилатись як на готовий): вхід - тека `package/master-data/` і alias бази;
вихід - JSON по файлах `{file, model, loaded, errors:[...]}`. Ім'я й інтерфейс - відкрите питання до C-00.

## Спосіб 2 (запасний): `odoo_execute` з методом `load`
Для кожного файлу в порядку README: прочитати заголовок і рядки CSV, викликати `load(fields, rows)` на моделі через
`odoo_execute` з явним `connection_id`. Поля - заголовок CSV (із `/id`), рядки - списки значень. У відповіді дивитись
`ids` і `messages`; повідомлення рівня error = помилка файлу. Точні параметри `odoo_execute` звірити через схему
інструмента перед першим викликом, не вгадувати.

## Спосіб 3: ручний режим (BA)
Якщо жоден спосіб недоступний: у звіті «імпорт не виконано агентом», MD-import = SKIPPED (це **не готово**); BA імпортує
вручну (maturity <= 1) і вносить результат у розділ «Тест-імпорт».

## Правила
- Спроба = нова чиста база. Після помилки стара база забруднена: xmlid першої спроби можуть замаскувати помилку.
- Номер/дату бази й SHA шаблонів записати в «Тест-імпорт».
- Перед імпортом перелік `ir.module.module state=installed` має збігатися з переліком у README (Крок 3).
- Після кожного виклику звірити `connection.db` з очікуваною базою; не збіглося - зупинка.
