# Пастки Odoo 19, що ламають імпорт майстер-даних

Лише поля й моделі даних; загальні пастки коду й XML - `boost:odoo19-lint`. Статус: **ще не пройдено `boost:source-check`** (одноразова перевірка 4 рядків таблиці з записом джерела/цитати/дати
сюди - відкрите питання мейнтейнера плагіна; на кожному запуску її не повторювати). На запуску: кожну пастку
підтверджує `odoo_get_fields` на тестовій базі (дешево), `boost:source-check` - лише для нових сумнівних полів, яких
тут немає. Розбіжність з реальною базою - перемагає база.

Джерело/цитата/дата перевірки: _не заповнено_.

| Було (до 18) | Очікувано в 19 (підтвердити) | Що робити в шаблоні |
|---|---|---|
| `product.template.type = product` | значення `consu` / `service` / `combo` + прапорець `is_storable` | `type=consu`, `is_storable=True` для складських; `product` не писати |
| `uom.uom.category_id`, `uom.category` | категорії одиниць прибрано; структура через `relative_factor`/`relative_uom_id` (звірити) | не додавати `category_id`; колонки - за `odoo_get_fields` |
| `res.partner.mobile`, `res.partner.title` | прибрано | не використовувати |
| `groups_id` / `res.groups.users` | змінені назви/зв'язки | групи - не майстер-дані, це A-12 |
| рядки техкарти | `mrp.bom` + `mrp.bom.line`, операції `mrp.routing.workcenter` | окремі файли; порядок bom -> line -> routing |

Загальні правила:
- Якщо `odoo_get_fields` не повертає колонку - прибрати з шаблону, не лишати «про запас».
- Selection-значення брати з `odoo_get_fields`, не з пам'яті й не з ТР.
- Посилання на стандартні записи (напр. xmlid одиниці «штука») - лише після перевірки в `ir.model.data` тестової бази.
