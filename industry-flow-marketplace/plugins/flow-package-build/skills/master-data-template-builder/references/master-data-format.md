# Формат шаблонів майстер-даних пакета (контракт)

Джерело цього контракту - скіл `master-data-template-builder` (A-13). Його ж читають `flow-client-delivery:client-data-migrator`
(B-06) і `flow-package-build:demo-base-builder` (A-15). Спільна копія для плагіна -
`plugins/flow-package-build/references/master-data-format.md` (є; цей файл - оригінал, при розбіжності чинний він).
Зміна контракту = зміна версії плагіна, бо B-06 і A-15 на нього спираються.

## Файли
- Стандартні моделі: `package/master-data/NN_<model>.csv`; моделі й поля `td_*`: `package/master-data/td/NN_<model>.csv`.
- `NN` - двозначна позиція в порядку імпорту (`01`, `02`...). Другий прохід для циклічних залежностей - `NNb_<model>.csv`.
- `<model>` - технічна назва моделі Odoo з крапками (`product.template`, `mrp.bom.line`).
- Один файл - одна модель. README.md - у `package/master-data/`.

## CSV
- UTF-8 без BOM, роздільник `,`, лапки `"` для значень з комою/переносом, перенос рядка `\n`.
- Перший стовпець - `id`: external ID у форматі `td_md.<model_slug>_<slug>` (`model_slug` - модель із крапок у `_`).
  Приклад: `td_md.product_template_dsp_18`. Однаковий `id` при повторному імпорті оновлює запис (ідемпотентність).
- Зв'язок many2one - стовпець `<field>/id` зі значенням external ID (з цього пакета або xmlid встановленого модуля).
- many2many - стовпець `<field>/id`, значення через кому в одній клітинці.
- Selection - технічне значення (`consu`), не підпис.
- Порожнє значення = порожня клітинка; булеві - `True`/`False`.
- Заголовки - лише технічні імена полів; кожен заголовок існує в `odoo_get_fields` тестової бази.
- Рядків даних у кожному файлі >=1 (ціль 2-3), вигадані галузеві приклади (`references/fictional-examples.md`).
