# Чек-лист рецензента: Концепція пакета

Крок: A-20. Підключається ключем наряду `review.checklists: [concept.md]`; агент `flow-reviewer` завантажує його перед рецензією.

**Спершу відкрий результат** — concept/features.md, screens.md, scenarios.md, BOX.md, SALES.md, REJECTED.md, AI-DECISIONS.md, OWNER-INTAKE.md. Висновок за самим текстом звіту без відкриття результату недійсний.
Серйозність: кожен пункт із відповіддю «ні» = **major**; minor, що впливає на рішення власника (обсяг, відкинуте, редакції), піднімається до **major**.
Вихід — список зауважень `{серйозність, місце, що не так, що зробити}` (формат — `agents/flow-reviewer.md`); пункт без перевірки очима не позначай «так».

## Пункти
1. [ ] Концепція відповідає анкеті (редакції, ICP, `todo_data`, бренд); рекомендація AI проти анкети показана як розбіжність, а не підмінює анкету (С-01).
2. [ ] Кожна роль має сценарій «день з життя»; кожна функція F має крок сценарію; роль-покупець має екран (дашборд керівника).
3. [ ] Вето власника з `flow/decisions.md` враховано: функція повернута в концепцію й не відкинута знову; позиції `do_not_do` анкети є в REJECTED з причиною «рішення власника».
4. [ ] Основа кожного екрана — одна з `Стд CE · Стд EE · td_ · ToDo-готовий · Інтегр` і для CE, і для EE; «готовий модуль ToDo» узгоджено з `REUSE.md`.
5. [ ] `BOX.md` і `SALES.md` заповнені за шаблонами (усі розділи, без плейсхолдерів); `AI-DECISIONS.md` має рядки A-20 (≤15 рядків «Рішення», без грошей).
6. [ ] Числа в BOX/SALES збігаються з `facts.yaml` (є результат `check_facts` без FAIL; звір 3 числа вибірково); у BOX/SALES немає окупності, TCO, годин і цін коробок (тарифи — лише дослівна цитата власника).
7. [ ] Брак болів/розмітки/тріалів не зупинив концепцію; слабкий довід = «ризик, перевірити на пілоті» (план A-23).
8. [ ] Позицію без болю з джерела немає у функціях (або позначено `ризик: перевірити на пілоті`).
9. [ ] (major) Для рядків з основою «Стд + td_» у `FUNCTIONAL-MAP.md` (колонка «Основа») або `features.md` (не в `screens.md`, де значення лише з переліку) названо стандартні об'єкти-джерела й окремо, що додає `td_` (розрахунок / відображення / ввід лише якщо стандарту немає); ввід даних стандартного модуля (закупівля, склад, виробництво) у `td_` не закладено.

## Вердикт
Зауваження major — повернення виконавцю (до `review.max_rounds` + 1 контрольний круг). Лише minor, що не впливають на рішення власника, — прийняти з переліком.
