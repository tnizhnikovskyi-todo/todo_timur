# Чек-лист рецензента: Концепція пакета

Крок: A-20. Підключається ключем наряду `review.checklists: [concept.md]`; агент `flow-reviewer` завантажує його перед рецензією.

**Спершу відкрий результат** — concept/features.md, screens.md, scenarios.md, OWNER-BRIEF.md, BOX.md, SALES.md, REJECTED.md, OWNER-INTAKE.md. Висновок за самим текстом звіту без відкриття результату недійсний.
Серйозність: кожен пункт із відповіддю «ні» = **major**; minor, що впливає на рішення власника (гроші, обсяг, відкинуте, редакції), піднімається до **major**.
Вихід — список зауважень `{серйозність, місце, що не так, що зробити}` (формат — `agents/flow-reviewer.md`); пункт без перевірки очима не позначай «так».

## Пункти
1. [ ] Концепція відповідає анкеті (редакції, амбіція, ICP, тарифи, `todo_data`); рекомендація AI проти анкети показана як розбіжність, а не підмінює анкету (С-01).
2. [ ] Кожна роль має сценарій «день з життя»; кожна функція F має крок сценарію; роль-покупець має екран (дашборд керівника).
3. [ ] Жодної позиції зі списку `do_not_reject` у відкинутому без посилання на рішення K1; повернуті власником (G4а) не відкинуто знову.
4. [ ] Основа кожного екрана — одна з `Стд CE · Стд EE · td_ · ToDo-готовий · Інтегр` і для CE, і для EE; «готовий модуль ToDo» узгоджено з `REUSE.md`.
5. [ ] `BOX.md` і `SALES.md` заповнені за шаблонами (усі розділи, без плейсхолдерів); `OWNER-BRIEF.md` — §1–10.
6. [ ] Числа в OWNER-BRIEF/BOX/SALES збігаються з `facts.yaml` (у брифі є результат `check_facts` без FAIL; сам звір 3 числа з `facts.yaml` вибірково); ціни й курс — з однією датою.
7. [ ] Брак болів/розмітки/тріалів не зупинив концепцію; ризик є в плані A-23 (К-01).
8. [ ] Позицію без болю з джерела немає у функціях (або позначено `owner-decision` з ризиком).

## Вердикт
Зауваження major — повернення виконавцю (до `review.max_rounds` + 1 контрольний круг). Лише minor, що не впливають на рішення власника, — прийняти з переліком.
