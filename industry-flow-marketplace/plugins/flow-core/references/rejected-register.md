# Реєстр відкинутого: формат і кроки-власники

Єдиний формат обліку позицій, відкинутих у кроці (функції, конкуренти, підсегменти, модулі, ідеї). Мета: нічого не зникає мовчки; власник бачить, що відкинуто, чому й за якої умови повернеться (L§13). Великий шаблон A-03b/A-20 — `REJECTED.tpl.md` (`flow-research/references/templates/`) поверх цього формату.

## Колонки (8, обов'язкові)
`ID` · `назва` · `група` · `причина` · `доказ` · `умова повернення` · `де живе зараз` · `рішення (K1/гейт, дата)`

## Формат ID позиції
Шаблон `REJ-\d{3}` (наприклад `REJ-007`), наскрізна нумерація в межах файла реєстру; той самий шаблон — в `id-patterns.md`; приклад у `REJECTED.tpl.md`. Групи `G1…G4а` — це значення колонки `група`, а не ID: вони не є `G-xx` (прогалини повноти, `\bG-\d{2}\b`). Позначка групи `G4а` пишеться **кириличною «а»** (U+0430); `check_rejected.py` (`REJ-fields`) перевіряє формат ID і значення групи з набору `G1|G2|G3|G4|G4а` (латинська `a` — помилка форми).

## Групи (5)
| Група | Зміст |
|---|---|
| `G1` | поза пакетом |
| `G2` | не в першій версії |
| `G3` | інший підсегмент/профіль |
| `G4` | понижено в попередньому артефакті |
| `G4а` | повернуто рішенням власника |

Позиції з `do_not_reject` анкети (`OWNER-INTAKE.md`) у реєстр відкинутих не потрапляють; конфлікт — до власника (К-02). Позиція з `G4а` не відкидається повторно без нового рішення власника.

## Правила
1. Перезапуск кроку (resume, `recalc`, повернення): спершу перечитати наявний реєстр; для кожної позиції перевірити «умову повернення» на нових фактах — виконана -> запропонувати власнику зняти рішення (запис у журнал знятих), не відкидати повторно.
2. Немає доказу — в колонці «доказ» значення `гіпотеза` (не порожньо й не вигадане джерело).
3. Реєстр показується людині разом із рішенням (K1, гейт A-20c, A-21): власник бачить відкинуте ДО підтвердження (К-02).
4. «Що з уже зробленого вважаємо зайвим» — позиції з уже існуючим артефактом: у колонці «де живе зараз» шлях до нього; артефакт не видаляти без рішення власника.
5. Один файл `research/REJECTED.md` ведуть два кроки: A-03b створює й пише G1–G3; A-20 дописує лише G4/G4а (не перезаписує чужі рядки; ID `REJ-xxx` продовжує нумерацію).

## Місце й журнал
- Файл `<артефакт>-rejected.md` поруч з артефактом або розділ `## Відкинуто` в самому артефакті; у звіті — `rejected_count`, `rejected_ref` (`report-format.md`). Формат `rejected_ref`: `<шлях до файла>` для окремого реєстру; для розділу в артефакті — `<шлях>#відкинуто` (розділ `## Відкинуто`; так у A-01, A-04, A-23 тощо).
- Журнал знятих рішень (позиція повернута з відкинутих) — розділ `## Журнал знятих рішень` з датою і посиланням на рішення (`flow/decisions.md`).
- Перевірка — `check_rejected.py` (REJ-exists, REJ-fields, REJ-dnr, REJ-count).

## Кроки, зобов'язані писати реєстр
A-01, A-03b, A-03c, A-04, A-05/B-01, A-20, A-20c, A-21, A-23, B-02, D-02, D-05, A-07.
Крок із переліку без реєстру (або з порожнім `rejected_ref` при `rejected_count > 0`) — FAIL автоперевірки; «нічого не відкинуто» записується рядком у розділі `## Відкинуто`.
