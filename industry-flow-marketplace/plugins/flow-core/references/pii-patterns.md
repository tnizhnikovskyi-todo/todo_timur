# Шаблони виявлення ПДн і чутливого (спільні для автоперевірок)

Єдине місце regex для `check_privacy.py` (`PRV-pii`, `PRV-raw-place`), `flow-autocheck`, `concept-mapper`, `past-projects-analyzer`, `package-usage-metrics` та інших `*-pii` перевірок. Скрипти копіюють шаблони звідси; змінювати — тут і в скриптах разом. Перевірка: `python3 -I - < script` або `grep -nEi`/`grep -nP` (Perl-режим для lookbehind) по файлу; будь-який збіг поза блоком коду з вигаданим прикладом = FAIL з типом і номером рядка (без самого значення в звіті).

| Тип | Regex (Python `re`, `re.I`) | Примітка |
|---|---|---|
| email | `[\w.+-]+@[\w-]+\.[\w.-]+` | |
| phone | `(?<![\w:])(\+?380\d{9}\|0\d{9})(?!\w)` | також формат із пробілами/дефісами: нормалізувати (прибрати `[\s()-]`) і повторити |
| url/host | `\bhttps?://[^\s)>\]]+\|\b[\w-]+(\.[\w-]+)+\.(com\|net\|org\|ua\|io\|dev\|app)\b` | URL баз клієнта й сервісів у артефактах заборонені; `github.com/<org>/<repo>` допускається лише у `repo:` ідентифікаторах |
| ip | `\b(?:\d{1,3}\.){3}\d{1,3}\b` | |
| login | `\b[\w.-]+@(?!example\.)[\w.-]+\b` за контекстом логіна; пара `login[:=]\s*\S+` | |
| secret | `(password\|passwd\|pwd\|api[_-]?key\|token\|secret)\s*[:=]\s*\S+` | |
| ПІБ (кирилиця) | `\b[А-ЯІЇЄҐ][а-яіїєґ'’-]+\s+[А-ЯІЇЄҐ][а-яіїєґ'’-]+\s+[А-ЯІЇЄҐ][а-яіїєґ'’-]+\b` | три слова з великої; хибні спрацьовування (назви посад/процесів) — позначати MANUAL, не ігнорувати мовчки |
| ЄДРПОУ/IBAN | `\bUA\d{2}[\s\d]{20,}\|ЄДРПОУ\D{0,5}\d{8}\b` | |
| суми | `(\d[\d\s.,]*\s?(грн\|₴\|\$\|€\|USD\|UAH\|EUR\|тис\.\|млн\|млрд))\|([$€₴]\s?\d)` | лише для документів, де комерційні суми не дозволені (концепція, прототип, звіти без `commercial`) |
| назва клієнта | денілист із **колонки назви клієнта/проєкту** `_input/sources.md` (за рядком заголовка таблиці) + stdin | ідентифікатори (project_id, repo, recording_id) і підставу обробки в денілист не класти |
| код клієнта | `\b[KКП]-\d{2,3}\b` (лат. `K`, кир. `К`, `П`) | **дозволено** (К-07): коди клієнтів K-xx/П-xx — норма для висновків; не вважати ПІБ/назвою |
| сума угоди (internal-raw) | рядок із кодом клієнта (`[KКП]-\d{2,3}`) + сума (число з `грн\|₴\|$\|€\|USD\|UAH\|EUR\|тис\|млн\|млрд`) + слово-маркер угоди (угод/договір/контракт/замовлен/рахунок/оплат/invoice/deal) — як у `check_privacy.py` (`PRV-pii`) | FAIL (`PRV-pii`); суми окремих угод у висновках заборонені |
| цитата клієнта (internal-raw) | **автоматично не перевіряється**: `check_privacy.py` не шукає прямої мови; `PRV-raw-place` ловить лише згадку `internal-raw`/посилання на `research/sources/` поза текою sources. Дослівні цитати клієнтів у висновках заборонені правилом, тримає його рев'ю (чек-лист) | цитати перевіряє рецензент за чек-листом (очима) |

Режими:
- `strict` (за замовчуванням): усі типи, крім «суми» й «назва клієнта».
- `+sums`: додати «суми». `+names`: додати денілист клієнтів.
Результат у `checks[]`: `{id: <X>-pii, status: PASS|FAIL|MANUAL, msg: "<тип>:<файл>:<рядок>"}`; значення збігу в звіт не писати.

Правило місця (К-07, К-19): файли в `docs/industries/<галузь>/research/sources/` — єдине дозволене місце для `internal-raw`; перевірка `PRV-raw-place` вважає FAIL згадку `internal-raw`/посилання на `research/sources/` поза цією текою (сума угоди — через `PRV-pii`; цитати клієнтів скрипт не розпізнає, див. вище) (у `research/*.md`, `owner-page/`, `prototype-real/`, продаючих матеріалах). Класи `internal-aggregated` і `internal-raw` — `data-policy-template.md`.
