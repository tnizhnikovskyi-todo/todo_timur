# Модель стану: подія → поля Odoo

Технічні імена полів — `flow/ODOO_SCHEMA.md` (C-00, ще не створено; імена нижче — логічні, не вгадувати технічні).

## 1. Подія → що записується
| Подія (джерело) | Куди | Що |
|---|---|---|
| `run:` у чаттері задачі кроку | задача кроку | дзеркальні поля запуску (§2), маркер `task_id+msg_id` |
| `dispatch:` у чаттері C-01 | задача кроку (за `step`, `scope`, `task_id`) | стан: створено / відкладено / заблоковано рішенням <роль> / стоп-лист; `units_N` |
| кнопка «Затвердити / Повернути» | журнал рішень проєкту (+ «Параметри флоу», реєстр питань) | рядок журналу, §4 |
| подія з `event-rules.md` | проєкт клієнта | прапорець + дата + «підтверджено PM» |
| табель `account.analytic.line` | посилання з задачі кроку | суми годин за задачею й роллю; без коментарів |

## 2. Обов'язкові поля запуску
`step, scope, attempt, started, finished, result (done|returned|escalated|stopped), skill_versions (точний semver),
usage.cost_usd, usage.tokens_in, usage.tokens_out, pr (url або null з причиною), data_sources`.
Умовні: `returned_to` (реальний код картки) при `returned`; `escalated_to` + дата при `escalated`; непорожній `data_sources`
при `client_data: personal`; `stop_reason` при `stopped`. Поля, яких немає, — не добудовувати: `run_status: неповний`.
Розширення runner'а, які можна переносити: `attempts_in_run, returns, models_used, audit, stop_reason`.

## 3. Білий список `flow/runs/<YYYY-MM>/<step>-<scope>-a<attempt>.yaml`
`step, scope, attempt, started, finished, result, returned_to, escalated_to, skill_versions, model, usage, pr,
data_sources, run_status, checks[].id, checks[].status`. **Не експортувати:** `memo`, `checks[].msg`, тексти зауважень,
`observations` (лише лічильник), будь-які поля клієнта поза ідентифікатором за DATA_POLICY.

## 4. Типи записів журналу рішень
Рядок: `decision_id, тип, рішення (затверджено|повернено), роль, користувач, дата/час кнопки, крок, підстава/посилання`.
Типи: гейт кроку; шлюз «Потрібні сесії з еталонними клієнтами?» (з критерієм і роллю); вікно поставки в прод (B-12);
зняті відхилення при оновленні (B-11, фаза 0); параметр флоу; закриття відкритого питання. Повний перелік і формат —
`flow-core/references/flow-state.md` (Відкрите питання: файл ще не створено).

## 5. Ключі ідемпотентності й стабільні ключі рядків
Подія: `task_id + message_id`. Рядок запуску: `step|scope|attempt`. Рішення: `decision_id`. Клієнт: `client_id`.

## 6. Межі стану
Поля клієнта (крок пулу B, прапорці, планові дати) — лише в проєкті клієнта. У рядку/проєкті пакета — лише стан пакета.
Планові дати — з Planning, SOW (B-03), `leadDays` карток; завантаження ролей — перелік, не розрахунок.
