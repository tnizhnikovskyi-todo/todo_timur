# Розв'язання версії Odoo

Порядок джерел N (перше непорожнє):
1. input `odoo_version` (dispatch);
2. суфікс `-odoo<N>` у input `package_tag` (формат тега `vX.Y-odoo<N>`);
3. суфікс гілки `upgrade/vX.Y-odoo<N>` (push/PR на гілці D-03);
4. суфікс `-odoo<N>` тега клієнта з `clients/REGISTRY.md`;
5. інакше **19**.

Тег чи гілка без суфікса -> 19. Суфікс не збігається з `-odoo[0-9]+$` -> `resolve` падає з текстом помилки, не мовчки 19.

## Непідтримка
Агент перевіряє за текстом/`--help` скриптів `tools/odoo/` (C-00), чи є параметр версії/образу і чи він приймає N. Не знає — вважає, що ні.
- N = 19 і параметра немає — допустимо (скрипти C-00 за замовчуванням під 19, якщо це підтверджено текстом скрипта; інакше відкрите питання).
- N != 19 і параметра немає -> `odoo_supported=false` -> job `ci` **червоний**: «Odoo N: вибір образу не визначено, статус C-03 недійсний».
  Прогін на 19 замість N заборонений. У `memo` — відкрите питання до C-00.
- Гілка D-03 і теги `-odoo<N>` до визначення механізму мають недійсний статус C-03 (картка C-03, `done`).
