# Формат уроку `flow/lessons/LSN-xxx.md` (К-24)

## 1. Файл
```
# LSN-001 <коротка назва, ≤80 символів>
- дата: 2026-11-11
- крок: A-20c
- скіл: flow-research:concept-presentation
- версія_скіла: 0.1.0
- серйозність: низька|середня|висока|критична
- клас: текст скіла|reference/шаблон|нова автоперевірка|новий евал|процес|параметр/рішення|середовище|навчання
- статус: відкрито|правка внесена|евал зелений|закрито|не помилка   # єдиний перелік статусів; «повтор» — не статус, а `repeat_of` при статусі «відкрито»
- repeat_of: LSN-000|—
- примітка_повтору: правка не спрацювала
- сигнали: SIG-001, SIG-002
- частота: <скільки разів, у яких репо (коди)>
- вартість: <$/раунди/години або н/д>
- докази: <шляхи observations, PR, задачі Odoo>
- fix_ref: <шлях `flow/lessons/drafts/LSN-xxx.md` (чернетка правки) | pr#N, якщо PR уже відкрито | н/д лише для «не помилка»>
- eval_ref: <id запропонованого кейса (блок «Пропозиція евал-кейса» у чернетці)>
- eval_статус: запропоновано|зелений   # «зелений» ставить лише наступний прогін після C-04 (eval-builder створив і прогнав кейс)
- правка_внесена: <дата | —>
- ескальовано: <дата ескалації AI-інженеру, якщо відкрито >3 робочих днів | —>
- евал_зелений: <дата, коли евал став зеленим | —>
- закрито: <дата, коли 2 тижні без повтору | —>
```
ID — `LSN-\d{3}` (`id-patterns.md`). **Автор `flow/lessons/LSN-xxx.md` і `flow/lessons/drafts/LSN-xxx.md` — лише `skill-retro`** (у `where` кроку C-08R). **`flow/lessons/INDEX.md` пише лише `flow-state-keeper`** (автоекспорт C-02, `state_export.py render`, колонки `LSN | дата | крок | суть | скіл | статус`); `skill-retro` файл не створює й не змінює: він віддає рядки `lesson: {...}` у звіті (блок `retro:`), з яких keeper веде облік. Файли `LSN-xxx.md` keeper не рендерить. Тож кожен файл має одного автора; PR гілки C-08R і PR автоекспорту не конфліктують. Перелік статусів — лише цей (§1).

**Чернетка правки** = файл `flow/lessons/drafts/LSN-xxx.md` у гілці кроку (що змінити, де, чому, текст правки або diff) і блок **«Пропозиція евал-кейса»** (id, `source: "lesson LSN-xxx"`, на якій `скіл@версія` має бути червоним, очікуване). Сам кейс у `evals/` C-08R не створює (поза `where`): його створює й проганяє `eval-builder` нарядом C-04 (`params.lessons [LSN-…]`); до цього `eval_статус: запропоновано`. PR у репо каталогу плагінів відкриває runner або AI-інженер після кнопки «Затвердити пакет»; скіл PR не відкриває й у чужі репо не пише.

## 2. Кластеризація
- Однакова причина з різних репо/кроків -> один урок, `частота` росте, докази додаються.
- Збіг із **закритим** уроком -> новий LSN, `repeat_of`, серйозність на рівень вище, `примітка_повтору: правка не спрацювала` (вхід для розбору: чому правка не спрацювала).
- Серйозність: `критична` — витік даних, ПДн, завдана шкода продові; `висока` — результат непридатний/повернуто людиною; `середня` — доробки людини; `низька` — стиль, дрібниці.

## 3. Класи й правка
| Клас | Правка (чернетка) | Евал |
|---|---|---|
| текст скіла | PR у `plugins/<плагін>/skills/<скіл>/SKILL.md` | кейс у `evals/evals.json` скіла |
| reference/шаблон | PR у `references/` | кейс, що читає шаблон |
| нова автоперевірка | `references/checks/*.yaml` + скрипт (WP автоперевірок) | фікстури `-ok/-bad` |
| новий евал | лише кейс | — |
| процес (карта флоу/картка/роль) | PR у схему флоу (`flow-map.md`, `step-cards.md`) | кейс оркестратора |
| параметр/рішення людини | пункт у пакеті дня для Власника продукту | — |
| середовище (C-00) | пункт `c00-checklist.md`/`preflight.sh` | перевірка preflight |
| навчання людей | пункт для AI-інженера | — |

## 4. Закриття
`відкрито -> правка внесена -> евал зелений -> закрито`; закрито лише за 2 тижні без повтору (з дати `евал_зелений`). Ескалація AI-інженеру (>3 робочих днів) — **лише для статусу `відкрито`** (правку не внесено): у уроці з'являється `ескальовано: <дата>` (`check_retro.py`: без поля `RET-stale` FAIL, з полем WARN). Для `правка внесена` строк рахується від `правка_внесена` до зеленого евалу (понад 5 робочих днів без зеленого — лише WARN, без ескалації). `евал зелений` у межах 14 днів — нормальне очікування, без WARN. `RET-close`: статус `закрито` (і `евал зелений`) дозволений лише з `eval_статус: зелений`, датами `евал_зелений` і `закрито` (≥14 днів різниці) і без уроку з `repeat_of` на нього між цими датами. Урок не видаляється.
