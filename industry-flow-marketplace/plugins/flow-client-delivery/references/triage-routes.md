# Тріаж звернень: єдина таблиця «тип -> маршрут» (B-09, B-10, B-13)

Спільна для `support-desk`, `product-decision-drafter` (факти пілота), `backlog-triage`. Тип ставить AI за ознаками й AC; маршрут — лише з цієї таблиці. Серйозність — `support-desk/references/severity-scale.md` (чернетка, затверджує Власник продукту). Зміна таблиці — PR Тімліда.

## Типи й маршрути
| Тип | Ознаки | AC потрібен? | Маршрут (крок) | Перший статус | Наступні статуси ставить |
|---|---|---|---|---|---|
| баг конфіг | поведінка стандартного Odoo або налаштування не відповідає AC/`config-log.md`; помилка стандартного Odoo — теж тут | так (інакше «потрібен AC — Підтримка») | B-04 (виправлення; поставка B-12, виправлення — B-13) | в роботі (B-04) | «виправлено на тесті» — B-13; «застосовано в прод» — B-12 (людина); «закрито» — Підтримка після підтвердження клієнта |
| баг код | модуль `td_*` або доробка клієнта працює не за AC | так | B-05 (код, pr-review, CI C-03) -> B-13 -> B-12 | в роботі (B-05) | так само |
| дані | імпорт, звірка, дублі, маппінг | ні (є план міграції) | B-06 | в роботі (B-06) | B-06 -> B-12; закриває Підтримка |
| навчання | користувач не знає, як; поведінка правильна | ні | B-07 (матеріали) | в роботі (B-07) | Підтримка |
| дефект пакета | помилка в пакеті (модулі, конфіг, майстер-дані), що відтворюється поза клієнтом | так для бага | залежно від серйозності (нижче) | передано (D-02) / обхід | A-19 / D-02 |
| нова вимога | функції немає в ТР/AC; лист каже «хочемо, щоб…», а не «не працює» | ні | D-02 («Запити в D-02») | передано в беклог (D-02) / передано в D-02 | D-02 (рішення Власника продукту) |
| платформа-інфраструктура | недоступність, швидкодія, бекап, доступи, пошта/інтеграції | ні | Підтримка/Тімлід (поза пакетом) | очікує Підтримку | Підтримка |
| консультація | питання «як», без дефекту; ≥2 разів те саме -> перекваліфікувати в «навчання» з посиланням на ID | ні | Підтримка; повтор -> B-07 | очікує Підтримку | Підтримка |

## Дефект пакета × серйозність
| Серйозність | Маршрут |
|---|---|
| критична | негайно `escalated_to: [Тімлід, PM]`; обхід (B-04 «відхилення від пакета» або B-05 тимчасовий патч) + рядок «Запити в D-02» з тим самим ID + повідомлення «Дефект пакета (hotfix)» для A-19 |
| висока | те саме без негайної ескалації |
| середня | «рішення Підтримки» (відкрите питання: межа не затверджена) |
| низька | D-02 («Запити в D-02») |

## Окремо від типу
- Категорія «помилка AI» (хибний результат AI дійшов до клієнта або Підтримка позначила) -> повідомлення в C-07 з ID; тип звернення при цьому визначається як зазвичай.
- Критичне звернення завжди `escalated`, не чекає решти тредів у запуску.

## Правила
- Статуси «застосовано в прод» і «закрито» AI не ставить.
- Після go-live повернення на B-08a–d неможливе: маршрути лише з таблиці.
- AC для бага шукається grep по ТР галузі / `ТР-доробок.md`; не знайдено -> тип не міняти, статус «потрібен AC — Підтримка», check FAIL для рядка.
