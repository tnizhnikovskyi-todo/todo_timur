# Редакція клієнта й «Відкинуто» — спільні правила скілів B-02, B-03, B-06, B-11, B-04/B-05

Канон: К-06, К-09, К-12; формат реєстру — `flow-core/references/rejected-register.md`; редакції пакета — `flow-package-build/references/editions-and-bridges.md`.

1. **Редакція клієнта — вхід, не припущення.** Джерело: параметр `edition` (`ce|ee`) в `clients/<клієнт>/answers.yaml` (із анкети клієнта, `questionnaire-builder`);
   якщо порожнє — `уточнити` (у fit-gap) або `waiting_human` (там, де без неї не можна продовжити). Редакцію не виводити з назви пакета чи припущень.
   Тег пакета має містити профіль цієї редакції (`package/config/manifest.yaml` -> `edition_profiles.<edition>`); немає — ескалація, не «підібрати».
2. **EE-модулі й мости `td_*_ee` — лише на EE-базі клієнта.** На CE-базі їх не ставимо й не обіцяємо; EE-база/код недоступні -> усе EE-залежне = «не перевірено» (WARN), не «готово».
3. **`contract_mode`** — параметр `answers.yaml` (юридично неоднозначне, §21 №17): скіл читає значення й переносить у документ як є; значення не вигадує й не змінює.
4. **«Відкинуто».** Вимога/позиція, яку ми не беремо (поза пакетом, не цього релізу, інший профіль), — рядок реєстру (8 колонок, `REJ-NNN`, група G1–G4а, причина, доказ або `гіпотеза`,
   умова повернення) у розділі `## Відкинуто` документа або `<артефакт>-rejected.md`; позиції `do_not_reject` власника не відкидаються. Автоперевірка — `flow-autocheck/scripts/check_rejected.py`.
5. **Дані.** Внутрішні дані ToDo — лише `internal-aggregated` (К-07) і лише для читання; `internal-raw` не потрапляє в документ клієнта. Дані клієнта — класи `personal/commercial` за `DATA_POLICY`.
