# Стан модулів через odoo-mcp

Лише тестова база (`test-<клієнт>`) або знеособлена копія (`anon-<клієнт>`, версія 2 відкладена після пілоту, q03) з allow-list наряду. Кожен виклик з явним
`connection_id`; після виклику звірити `connection.db`. Прод-alias -> стоп.

## Дозволено
- `odoo_search_read`, модель `ir.module.module`, домен `[["name","in",[<модулі «Склад пакета» нового тегу> + td_<к>_*]]]`,
  поля лише: `name`, `state`, `installed_version`, `latest_version`.
- `odoo_search_read` по `flow` лише для полів проєкту клієнта (логічні імена `project.package_tag`, `project.candidate_tag`,
  `project.pilot` з `flow/ODOO_SCHEMA.md`) і для задачі B-11 пілота (`task.step`, `task.scope_id`, стадія, `description`).
- Лічильники (`search_count`) цей скіл не знімає: в odoo-mcp немає окремого інструмента, а `odoo_execute` заборонено.

## Заборонено
`odoo_write`, `odoo_create`, `odoo_execute`; читання бізнес-моделей (партнери, замовлення, проводки, співробітники тощо);
будь-який виклик без `connection_id`; видалення.

## Семантика полів (увага: назви в Odoo інвертовані)
- `latest_version` — версія, **збережена в БД**, тобто реально встановлена (оновлюється при `-u`/установці).
- `installed_version` — computed: версія з маніфесту **на диску** (розгорнутого коду).
Тому порівнювати з маніфестом тегу треба `latest_version`, а не `installed_version` (підтвердити `boost:source-check`).

## Очікування
- `state = installed` для кожного модуля тегу й доробок;
- `latest_version` = версія з маніфесту модуля на тегу (`git show <тег>:package/addons/<модуль>/__manifest__.py`),
  звичайно `19.0.X.Y`; патч Z у версії модуля не відображається — не вимагати його;
- Нормалізація: Odoo зберігає версію як `19.0.<версія>`, якщо маніфест не починається з `19.0.`; тоді порівнювати з `19.0.<версія з маніфесту>`, інакше хибний FAIL.
- `installed_version == latest_version`; інакше -> FAIL «код розгорнуто, оновлення модулів не виконано» (Тімлід виконує `-u`).
- Модуль відсутній у відповіді або `state` не `installed` -> U-06 FAIL, рядок у «Стан модулів».

Чого не вдається побачити через `ir.module.module` (UI доробок, дані) — у `memo` як невпевненість, не як PASS.
