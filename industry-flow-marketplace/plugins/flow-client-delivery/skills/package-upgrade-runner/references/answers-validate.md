# Валідація `clients/<к>/answers.yaml` за схемою тегу

Схема — `package/templates/answers.yaml` на новому тегу (`git show <тег>:package/templates/answers.yaml`).
Скрипта валідації немає (відкрите питання; спільна перевірка може жити в `flow-core:flow-autocheck`). Правила вручну:

1. Кожен ключ VP-xx зі схеми має відповідь у `answers.yaml`; відсутній -> FAIL з переліком ключів.
2. Ключів, яких немає в схемі нового тегу, бути не повинно; позначені deprecated у схемі — лише як попередження.
3. Тип і допустимі значення кожної відповіді відповідають схемі; значення за замовчуванням з CHANGELOG, не підтверджене
   Клієнтом (немає в додатку з підписом) -> FAIL U-03.
4. «уточнити» / порожнє значення в обов'язковому ключі -> FAIL.
5. Файл не змінювати: помилки йдуть у `memo` і `returned` PM.
