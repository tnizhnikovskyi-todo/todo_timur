# Odoo 19: нотатки для імпорту (до підтвердження)

Позначка **підтвердити** = перед використанням перевірити `boost:source-check` за документацією Odoo 19; не
підтверджено -> не стверджувати, записати в memo, крок «очікує: виконує людина». Нотатки нижче — робочі
гіпотези, а не перевірені факти.

| Тема | Нотатка | Статус |
|---|---|---|
| Завантаження | `odoo_execute(<model>, "load", [fields, rows])` повертає `ids` і `messages`; перевіряти `messages` після кожного виклику | підтвердити |
| Ідемпотентність | рядок з наявним external ID (`id` у CSV) оновлює запис, а не створює новий | підтвердити |
| Тип продукту | у 19 тип товару й облік залишків задаються окремо (`type`, `is_storable`); не використовувати застарілі значення з 17- | підтвердити |
| Одиниці виміру | у 19 категорії одиниць прибрано — перед завантаженням звірити модель UoM у базі через `odoo_get_fields` (результат — у файл, не в контекст) | підтвердити |
| Складські залишки | через `stock.quant` (`inventory_quantity` + застосування інвентаризації), а не прямий запис `quantity` | підтвердити |
| Сальдо контрагентів і рахунків | відкривні проведення / початкові залишки за політикою бухобліку клієнта; рахунки — з плану рахунків у `config-log.md` | підтвердити; потребує рішення бухгалтера клієнта |
| Агрегати | `formatted_read_group` замість `read_group` у 19 | підтвердити |
| Поля `td_*` | є лише якщо модуль пакета встановлено (README тегу «Потребують модулів A-11») | перевірити в базі |

Загальне: структуру моделей читати через `odoo_get_fields` у файл; відсутній склад/журнал/рахунок —
повернення на B-04 (`runbook-executor`), не створювати самому.
