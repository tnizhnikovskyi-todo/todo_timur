# Звірка: що і як порівнювати

AI заповнює лише колонки Odoo і розбіжність; колонки джерела — BA з `totals.json`. Записи бізнес-моделей через
`odoo-mcp` не читати: лише лічильники й агрегати. Усі виклики — з `connection_id` `test-<к>`.

| Тип | Показник джерела / Odoo | Допуск |
|---|---|---|
| Довідники (одиниці, категорії, склади, ціни) | кількість записів | 100% або пропуски з кодами |
| Контрагенти | кількість після дедуплікації | 100% або пропуски з кодами (DUP — злито) |
| Номенклатура | кількість | 100% або пропуски з кодами |
| Складські залишки | кількість рядків і сума кількостей за складом (+ вартість, якщо ведеться оцінка) | сума — 0 |
| Сальдо контрагентів | сума дебету, сума кредиту | 0 |
| Сальдо рахунків | сальдо за рахунком | 0 |
| Техкарти / структури | кількість | 100% або пропуски з кодами |

## Домен імпорту
Записи повного завантаження — за external ID `mig_<к>.*` (`ir.model.data` з `module = 'mig_<к>'`). Пробні записи
вибірки (`module = 'migtest_<к>'`) у домен НЕ входять і до розбіжності не додаються. Поле-мітка замість
`ir.model.data` — Відкрите питання (A-13/C-00); до рішення використовувати `ir.model.data`.
- Кількість: `odoo_execute(<model>, "search_count", [[("id","in", <id з ir.model.data>)]])` або підрахунок за
  `ir.model.data` (`module = 'mig_<к>'`, `model = '<model>'`).
- Сума: агрегат `:sum` через `formatted_read_group` (Odoo 19) на тому ж домені. Назву методу й сигнатуру
  підтвердити `boost:source-check` до першого використання; не підтверджено -> «очікує: виконує людина».

## Розбіжність і пропуски
- Розбіжність = Odoo − джерело (знак зберігається). Суми/залишки: ненульова розбіжність = FAIL `MIG-recon`.
- Кількість < 100%: сума пропусків з кодами з `errors.csv`/`dedup-report.csv` має дорівнювати різниці; інакше FAIL.
- Статус рядка: `збіг` / `пропуски з причиною` / `розбіжність` / `очікує джерела` (колонки BA порожні).
- Сума в рядку, де для залишку немає показника суми, — помилка плану: повернути BA (звірка лише за кількістю не приймається).

## Перевірка часу операцій
Одна-дві ключові операції на обсягах пілота (з НФВ ТР: напр., відкриття списку номенклатури, проведення
документа). Час виклику через `odoo-mcp` + час завантаження з журналу BA. Немає НФВ -> вимірювання без порогу.
