# Режим «додаток» (б)

Додаток — новий запис у розділі «Додатки» підписаного SOW. Основний текст і попередні додатки не змінюються,
основний SOW не перепідписується. Зміни до підписаного SOW оформлюються додатковою угодою, а не новою редакцією SOW (рішення q12); додаток нижче — її текст-чернетка.
Режим викликають: B-03 (після B-05, зміна обсягу, зміна відповідей), B-11 фаза 0 (`package-upgrade-runner`).

## Нумерація
N = останній № у «Додатках» + 1 (немає додатків -> 1). Заголовок запису: `### Додаток №N (YYYY-MM-DD)`, дата — поле `date` наряду (інакше `run.started` першого звіту).

## Формат запису
```markdown
### Додаток №N (YYYY-MM-DD)
Підстава: <ТР-доробок після tr-review B-05 / запит на зміну обсягу <CR-N> / зміна відповідей анкети / нові питання анкети тегу <тег> (B-11)>
Тег пакета: <тег з наряду дослівно>
Зміст: <таблиця за джерелом>
Ціна й терміни: <лише якщо змінюється обсяг; кроки 3-4 SKILL.md для змінених позицій; інакше "без змін">
Підписи: Керівник напряму [плейсхолдер: роль, дата]. Клієнт [плейсхолдер: роль, дата].
```

## Джерела змісту (`addendum_source`)
| Джерело | Вхід | Таблиця змісту |
|---|---|---|
| `tr` | `clients/<к>/ТР-доробок.md` після tr-review | `AC ID | текст AC (дослівно) | позиція fit-gap`; підпис Клієнта = погодження AC |
| `scope` | `fit-gap.md` (змінені позиції) або CR | `ID | було | стало | відмітка | години | ціна | термін | приймання` |

Визначення «змінених позицій» для `scope`: порівняти рядки таблиці «Вимоги» fit-gap на новому SHA з таблицею «Позиції» підписаного `sow.md` за `FG-NN`: нові ID, зміна «Рішення»/«Год» або вимоги, знято. Збігається — не включати. Для CR без нового fit-gap — позиції з тексту CR, позначка «з CR-N».

| `answers` | `answers.yaml` (нові значення від BA/B-02) і попередній підписаний текст | `VP-xx | питання | було | стало` |
| `changelog` | `package/CHANGELOG.md`, розділ «Зміни анкети» нового тегу | `VP-xx | питання | допустимі значення | значення за замовчуванням (потребує підтвердження Клієнтом) | Відповідь Клієнта (порожньо)` |

Правила `changelog` (B-11 фаза 0): значення за замовчуванням — лише пропозиція; не підставляти його як відповідь
клієнта й не вважати прийнятим; змінені допустимі значення існуючих VP — рядок «було -> стало» і окремо
«поточна відповідь Клієнта X: допустима/недопустима за новими значеннями».

## answers.yaml
Скіл його **не змінює**. У `memo` — точний перелік ключів VP-xx для внесення BA/PM після підписаного додатка
(змінювати лише ключі з додатка, не ширше). Автоперевірка SOW-answers для (б) — повторний прогін після внесення.

## Автоперевірка
- `git diff <base-sha> -- clients/<к>/sow.md` змінює лише розділ «Додатки», новий № = останній + 1;
- AC додатка = `ТР-доробок.md` (ID і текст) для `tr`;
- підписи — плейсхолдери;
- тег додатка збігається з тегом наряду, а для `scope`/`tr` — з тегом основного SOW (інакше `memo`).
