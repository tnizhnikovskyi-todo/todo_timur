# Allow-list читання проду (`prod-ro-<клієнт>`)

Статус: **кандидати, не затверджені**. Затверджує Тімлід (C-00) після звірки кожної моделі й поля через `odoo_get_fields` на конкретній базі та `boost:source-check` для Odoo 19. Чого тут немає — читати заборонено. Інструменти: лише `odoo_search_read`, `odoo_get_fields`; `fields` вказувати завжди (без `fields` = усі поля = FAIL `HB-allowlist`).

## Формат рядка (його читає `check_help.py`)
`| модель | поля |` — поля через кому. Рядки нижче — рекомендовані кандидати (довідники й налаштування); наявність кожного поля підтверджується в режимі `prepare`.

| модель | поля |
|---|---|
| ir.ui.menu | name, parent_id, complete_name |
| res.groups | name |
| stock.warehouse | name, code |
| stock.picking.type | name, code, warehouse_id |
| product.category | name, parent_id |
| uom.uom | name |
| res.users | groups_id |

Примітки:
- `res.users` — лише запис самого автора питання (за адресою відправника), лише поле груп; інших користувачів не читати. Назва поля груп у Odoo 19 і допустимість — відкрите питання (Тімлід, Юрист); якщо `odoo_get_fields` поля не показує — вилучити рядок.
- Поля й моделі з рядків вище не гарантовано існують у базі клієнта: `prepare` позначає «не перевірено» або вилучає.

## Заборонено
`res.partner`, `hr.*`, зарплата, `account.*` (без дозволу клієнта в DATA_POLICY), транзакційні документи (замовлення, накладні, платежі), `res.users` інших людей, будь-що з паролями/ключами, `ir.config_parameter`.
