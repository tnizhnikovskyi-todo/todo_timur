# Класифікація вимог: з пакета / доналаштування / доробка

Єдина точка відліку — карта пакета на тегу (VP-xx зі схеми, модулі td_* з ALLOCATION, розділи CONFIG.md,
сценарії scenarios.md, CHANGELOG). Стандартний Odoo 19 і маркетинг пакета — не якорі.

## Дерево рішень
1. Є якір на тегу і вимога закривається ним **без змін** (значення VP-xx, наявна функція модуля, наявний сценарій)?
   → `з пакета`; місце = якір; години `0` (якщо немає робіт, окрім відповіді в анкеті).
2. Закривається налаштуванням без коду і не зачіпає файлів пакета: додаткові параметри/значення, маршрути
   погодження, фільтри/групування у стандартних звітах, права, шаблони документів, автоматизації без коду?
   → `доналаштування`; місце — найближчий якір або «немає в пакеті».
3. Потрібно хоч одне з: нова модель/поле, обчислення або логіка Python, серверна дія з кодом, звіт QWeb,
   імпорт/обмін/інтеграція, зміна поведінки модуля td_*? → `доробка`; місце «немає в пакеті» (або модуль, що
   змінюється, у примітці).
4. Пакет «має» функцію за описом, але якоря на тегу немає → не `з пакета`; клас 2 або 3 + рядок «Запити в D-02»
   типу «функція відсутня», якщо вимога типова для галузі.
5. Не впевнений між двома класами → обрати **вищий** (доналаштування vs доробка → доробка) і позначити в примітці та `memo`.

## Маркери доробки (не можуть бути «доналаштуванням»)
«автоматично рахувати/підставляти», нове поле з розрахунком, обмін з зовнішньою системою, імпорт за розкладом,
друкована форма зі складною версткою, нове подання з логікою, зміна алгоритму резервування/планування.
Подання клієнта «це лише налаштування» маркер не скасовує.

## Типи якорів
`VP-xx` (з допустимим значенням) · `td_<модуль>` з ALLOCATION · стандартний модуль із треку пакета ·
заголовок `CONFIG.md` · `S-xx` у `scenarios.md`. Якір має існувати на тегу з наряду (перевірка grep).

## Межові приклади
| Вимога | Клас | Чому |
|---|---|---|
| Новий варіант значення, що є в схемі VP-xx | з пакета | значення допустиме на тегу |
| Нового варіанта значення в схемі немає | доробка + запит D-02 «відсутній варіант значення» | схему пакета тут не змінюємо |
| Додаткове необов'язкове поле на формі без розрахунку | доналаштування, якщо поля Studio/налаштувань дозволені пакетом; інакше доробка і питання BA | пакет має визначати, чи дозволено |
| Автоматизація «при зміні статусу надіслати лист» без коду | доналаштування | без Python |
| Автоматизація із розрахунком за формулою на Python | доробка | код |
| Фільтр/групування у стандартному звіті | доналаштування | без коду |
| Друкований документ нестандартної форми | доробка | QWeb |
| Імпорт залишків із файлу клієнта | не вимога цього кроку: міграція даних (B-06); у fit-gap — лише рядок «міграція — B-06», якщо клієнт згадав | не плутати з функцією |
| Стандартний модуль Odoo, якого немає в треках пакета | доналаштування або доробка (залежно від робіт), місце «немає в пакеті» | пакет його не містить |
| Функція є в сценарії S-xx, але клієнт хоче інший порядок кроків | доробка, якщо змінюється логіка; доналаштування, якщо лише права/маршрут | |
