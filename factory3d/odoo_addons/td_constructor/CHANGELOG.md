# Журнал змін

## fix1 — «конструктор нічого не дає змінювати»

- Вибір під курсором (`pickAt`): активний шар перемагає все; далі шари, які можна редагувати; приховані шари й зони чужих
  шарів не вибираються; об'єкти шарів-накладок (будівля, інженерні мережі) — лише коли їхній шар активний; серед рівних
  перемагає менший габарит (верстат — над штабелем чи зоною, що його накриває).
- Вид «План»: обертання вимкнене (ліва кнопка й один палець панорамують), знімок лишається вирівняним по осях; 3D — як раніше.
- Накладка: зони на весь цех (> 10 % площі будівлі) на чужих шарах — лише контур, на активному — ледь помітна заливка;
  завіса відмітки шару прозоріша.
- Seed: `visible` шарів із `seed_site.json` тепер потрапляє в БД (дах, інженерні мережі, територія вимкнені за замовчуванням;
  раніше всі 31 шар вмикались одразу). Уже встановлені бази виправляє міграція 19.0.1.0.1 (`seed.resync_site`, лише поки площадка в стані сіда).

## 19.0.1.0.1 — порожній план публікації незміненого сіда

Публікація щойно посіяної площадки без правок мала пропонувати десятки змін (38 створень, 126 оновлень, 7 архівацій, 7
заборон «Конфлікт кодів»). Тепер на копії демо-бази план порожній: «Без змін» і жодної заборони.

- Варіант: прапорець `create_equipment` («Створювати обладнання»). Зведені варіанти сцени («Об'єкти сцени · …», роль паспорта
  `scene_*`) його вимикають: будівлі, планшети, світильники тощо не створюють `maintenance.equipment`; увімкнути можна свідомо.
- План: зведений паспорт «Об'єкти сцени» ніколи не записується в наявне обладнання (раніше понижував справжні паспорти:
  Socomec ATyS, Huawei LUNA, Hoval RoofVent, Signify…). Зона наявного обладнання публікацією не змінюється (її задає каталог
  base); для нового обладнання `td_zone_id` ставиться як і раніше.
- Сід: розміщення з наявним обладнанням, що має паспорт, стоїть на варіанті ЦЬОГО паспорта (`passport_variant`, геометрія
  зведеного варіанта збережена), як це було для верстатів.
- Місця на одну комірку (`floor_stack`, `code_style='exact'`): параметр `loc_kind` (stack, area, kit, bin, shelf,
  pallet_cell). Сід бере вид з каталогу base (`scene_locations.csv`) і з наявної локації Odoo (`adapt_slots`), тож незмінена
  розкладка не пропонує оновлення виду локацій. Майданчик відходів WASTE — не склад Odoo: його комірку вимкнено
  (перевизначення `disabled`), локація не створюється.
- Збіг локацій і обладнання враховує другий код сцени `td_alias`: ворота `DOCK-Wn` і майданчик `UNLOAD-n` — один запис
  Odoo; місце `UNLOAD-n` зв'язується з воротами без конфлікту й без пропозиції архівації `DOCK-Wn`. Збіг лише за barcode з
  іншим td_code лишається конфліктом.
- Міграція `19.0.1.0.1/post-migrate.py` (ідемпотентна, `seed.resync_site`): вимикає `create_equipment` у зведених варіантів
  і, лише поки площадка в стані сіда (чернетка не змінена відносно v1), переписує варіанти розміщень, параметри місць і
  перебудовує знімок v1 (`baseline.poses` зберігається). Записи Odoo (обладнання, локації, паспорти) не видаляються.

## 19.0.1.0.0 — перший випуск

- Моделі площадки, шарів, місць (шаблони стелажів → комірки), розміщень, варіантів обладнання, налаштувань перевірок, версій.
- Перевірки `fits`, `collide`, `service_free`, `aisles_free`, `load`, `utility_reach`, `fire` (OBB + SAT), золоті фікстури
  паритету з JS.
- Майстер публікації (збіг за `td_code`/`barcode`, без видалень, пропозиції архівації), знімки версій, відновлення чернетки.
- API-01…API-10: JSON-RPC, завантаження й віддача 3D-моделей; хук `_f3d_convert_model()` для STEP/IGES/IFC.
- Ролі технолог/комірник/інженер/менеджер, правила `ir.rule` + серверна перевірка шару.
- Seed «Меблеве підприємство» зі зв'язуванням наявних записів за кодом (`post_init_hook`).
- Шаблони комірок: додаткові параметри `index_digits`, `code_style` (`pallet_rack`), `loc_kind` (`shelf`) — щоб коди й види
  збігалися з уже наявними локаціями.
- Сід = уся 3D-модель переглядача: 31 шар (поле `group_name` — група у списку шарів) і всі 1078 кодованих об'єктів
  (`data/scene_inventory.json`, `tools/scene_inventory.py`; класифікація — `tools/scene_classify.py`, генерація —
  `tools/extract_seed.py`): стелажі-шаблони, одиночні місця (`code_style='exact'`, код комірки = код об'єкта), контури-зони,
  розміщення з автопаспортами «Об'єкти сцени» (роль `scene_<вид>`), люди й транспорт — `dynamic` (не беруть участі в
  collide/aisles/service/fire; публікація не створює для них обладнання).
- Знімок v1 «Імпорт із макета» містить `baseline.poses` — положення об'єктів, запечених у GLB (`{код: {x, y, z, L, W, H, yaw}}`;
  x, y — центр AABB, як `x_m`, `y_m` розміщень сіда): від них етап 2 рахує зсуви.
- `code_style='exact'` для всіх шаблонів з комірками: якщо шаблон дає рівно одну комірку, її код = `code_prefix`.
