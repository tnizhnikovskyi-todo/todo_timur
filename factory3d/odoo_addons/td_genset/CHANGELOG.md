# Журнал змін `td_genset` («Генератори»)

Формат версії — `18.0.<major>.<minor>.<patch>` (Odoo 18.0). Джерела вимог: ТР «Генератор SmartGen: моніторинг і
керування в Odoo (erp.todo.ltd)» v1.2 (`../ТР_SmartGen_генератор.md`), `../SPEC.md` (AC-01…AC-69), API ретранслятора —
`../relay_api.md`. Процедура розгортання — `../DEPLOY_TEST.md`.

## 18.0.1.0.0 — 2026-10-08

Перша версія: тестовий сервер ToDo (копія проду) → прод erp.todo.ltd. Odoo 18.0 (прод — Enterprise; збірка й тести —
Community 18.0), залежності лише Community: `base`, `mail`, `bus`, `web`, `maintenance`. Ліцензія OPL-1.

### Що входить — за етапами ТР (розділ 1.7)

Модуль встановлюється один раз з усіма трьома етапами; вмикаються вони поетапно перемикачами на картці генератора
(«Опитувати ретранслятор», «Дозволити команди») — без релізів.

**Етап 1. Моніторинг (на робочий API — лише читання)** — ФВ-1…ФВ-8, ФВ-25…ФВ-30, ФВ-37 (частково), ФВ-39…ФВ-43:

- картка генератора (`hostid` модуля CMM366B-4G, бак 145 L, контролер HGM6120N), підключення через ретранслятор:
  адреса й токен — лише в системних параметрах (`Налаштування → Генератори`, системний адміністратор);
- забір знімків щохвилини за курсором (`/readings`, сторінки по 500, курсор і знімки в одній транзакції), догон
  історії з «Починати історію з» (типово −30 днів) — події заднім числом без лавини тривог, підсумок у чатері;
- «Поточні дані» з омами датчиків (ключі `*_sensor_ohm` з 1.1.3 або сирий образ `raw=1` для 1.1.1), журнал 15 хв за
  київським часом, «Зв'язок» у шапці («Онлайн · N с тому»), стан ретранслятора («Перевірити зв'язок»);
- події: робота генератора (причини пуску й зупинки), відключення мережі, заправка, падіння рівня, керування не з
  Odoo (панель, застосунок SmartGen), тривоги контролера, зв'язок/немає даних;
- тривоги з ескалацією (ланцюжок «Черговий → Відповідальний → Керівник»), тихі години, «Прийняв», тестове
  сповіщення; сповіщення лише в Odoo (вхідні + push мобільного застосунку на EE);
- аналітика (graph/pivot за днями) і KPI 7/30 днів, експорт «Показань»/«Подій» шаблоном «Усі значення»;
- права: Співробітник / Адміністратор / Тех. адміністратор (без record rules — «усі бачать усе», рішення 1.3).

**Етап 2. Керування** — ФВ-9…ФВ-24:

- пульт (OWL): Авто, Ручний, Пуск, Стоп, Тест, автомати генератора й мережі — з підтвердженням кожної команди за
  знімком контролера, повторами, чергою (≤ 2 від Odoo), обробкою 409/403/401, «Не потрібно» за свіжим знімком;
- розклад (вікна Авто за днями тижня), дні-винятки, таймер «Робота поза графіком» (+15/+30/+60), тест з навантаженням
  і без, «наступна подія», літній/зимовий час, пропущені переходи; журнал команд; живе оновлення через bus;
- стоп-крани: «Опитувати ретранслятор» і «Дозволити команди» (за замовчуванням вимкнені).

**Етап 3. Паливо і ТО** — ФВ-31…ФВ-36:

- місця зберігання, каністри, надходження, рух запасу, заправка генератора зі звіркою з подією «Заправка»,
  витрата (L/год, L/kWh, вартість), калібрування датчика (Ом → L) і «Перерахувати літри»;
- ТО за мотогодинами/місяцями через стандартне «Обслуговування»: обладнання генератора, авто-заявка ТО, тривога
  «Термін ТО», новий відлік після закриття заявки (закриває лише тех. адміністратор).

### Підготовка до проду (08.10)

- **«Дозволити команди»** — у формі лише показ стану; увімкнення — кнопкою «Дозволити команди» (тех. адміністратор) з
  підтвердженням «Дозволити команди на справжній генератор?», вимкнення — «Заборонити команди» одразу, без діалогу.
  Хто й коли — трекінг поля і нотатка в чатері генератора.
- **Деінсталяція** (`uninstall_hook`): системні параметри `td_genset.*` — адреса, **токен** ретранслятора, таймаут —
  видаляються (Odoo сам видаляє лише записи з xml id: cron, дії, групи, таблиці `td_genset_*`).
- **Копія бази** (`data/neutralize.sql`, стандарт Odoo 16+): `odoo-bin neutralize`, відновлення/дублювання бази з
  «neutralize» → на всіх генераторах вимкнено опитування і команди, токен видалено, cron модуля вимкнено. Тестовий
  сервер ToDo — копія проду: без цього копія керувала б справжнім генератором разом із продом.
- **Логи без спаму:** нормальна робота (знімок без змін) у лог модуля нічого не пише; повторювані помилки
  (ретранслятор недоступний, 401, збій кроку cron, ескалації) — WARNING один раз, далі DEBUG, нагадування раз на
  годину, відновлення — один INFO (`models/td_logging.py`).
- **Мультикомпанійність** (на проді 5 компаній): команда ТО і категорія обладнання «Генератори» — без компанії
  (спільні), обладнання й заявки ТО — у компанії генератора, без помилки `check_company` для генератора іншої
  компанії; збій створення заявки ТО більше не відкочує сторінку знімків (окремий savepoint).
- **Сповіщення для мобільного застосунку:** тема — «<генератор>: <тривога>», у тексті — генератор і час виникнення
  за Києвом (push `mail_mobile` зрозумілий без відкриття Odoo); інформаційні події — з генератором і часом.
- `smartgen/tools/preflight_relay.py` — передпольотна перевірка ретранслятора з сервера (лише GET) і часових поясів.
- Тести: +10 (`tests/test_w6_prod_readiness.py`) — безпечні значення за замовчуванням, кнопки й трекінг команд,
  деінсталяція, нейтралізація, логи, мультикомпанійність, тексти сповіщень, ретранслятор 1.1.1 і `command: null`.

### Відомі обмеження і беклог

- **Не перевірено на Enterprise** (у середовищі збірки лише CE): темна тема, мобільний застосунок Odoo і push
  (`mail_mobile`/OCN), форма на телефоні в `web_enterprise` — перевірка руками на тестовому сервері
  (`../DEPLOY_TEST.md`, розділ C).
- **Справжній генератор:** стенд лише емулює контролер; перші «Пуск»/«Стоп» — лише за протоколом етапу 2 з людиною
  на об'єкті. Питання **О-1**: чи бере HGM6120N навантаження в режимі Ручний сам (якщо так — після «Пуску» з Odoo
  з'явиться хибне «Керування не з Odoo»; виправлення — після перевірки на об'єкті). Поведінка `stop` на контролері
  (`relay_api.md` §11) — зафіксувати під час етапу 2.
- Беклог приймання: **D-10** (діалог пульта не попереджає заздалегідь про «Не потрібно»), **D-11** (формулювання
  повторів у журналі команд, примітка руху палива), **D-12** (графіки за показаннями — по днях: обмеження graph-подань
  Odoo 18; розрив даних видно лише в журналі), **ENV-1** (PostgreSQL без `Europe/Kiev` + tz користувача з браузера —
  перевірка `preflight_relay.py --psql`, користувачам — Europe/Kyiv).
- Беклог інтеграції: команда з пульта в ту саму хвилину після межі вікна розкладу перекривається переходом
  (SPEC §4.1, «Беклог інтеграції»).
- Беклог безпеки: SUGGESTION-1 (record rules за компаніями — не робили, суперечить рішенню 1.3), SUGGESTION-3
  (обмежити підтипи `message_post` для не тех. користувачів), SUGGESTION-4 (`requests` `trust_env = False` — лише
  якщо на сервері немає проксі для вихідного HTTPS).
- Беклог ревю коду: п. 9–17 (`../ЗВІТ_РЕВЮ_td_genset.md`, «Статус виправлень»).
- Ретранслятор 1.1.1: оми датчиків — із сирого образу `raw=1` (трафік знімків ≈ ×5); після оновлення ретранслятора до
  ≥ 1.1.3 модуль сам перейде на ключі `*_sensor_ohm`.
- Один ретранслятор і один токен на всі генератори (рішення 1.8-10); OWL-дашборд «Аналітика» не входить (варіант Б).
- Odoo сам пише в лог INFO про кожен запуск cron (`odoo.addons.base.models.ir_cron`, ≈ 4 рядки на запуск, три
  хвилинні задачі модуля) — це не модуль; приглушити можна `--log-handler odoo.addons.base.models.ir_cron:WARNING`.
- Регламент ТО: якщо мотогодини генератора вже більші за «Перше ТО» (типово 30 мотогодин), заявка «ТО-1 після
  обкатки» і тривога «Термін ТО» створяться одразу після першого забору — регламент заповнити до ввімкнення опитування.
