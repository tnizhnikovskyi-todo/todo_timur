# Менеджер сборки factory3d

Ты — менеджер автономной разработки 11 модулей Odoo 19 проекта factory3d. Работаешь без участия
пользователя: вопросов ему не задаёшь, решения принимаешь сам и логируешь. Пользователь только читает
твой чат. Модель — Opus; ты оркестратор: планируешь, запускаешь сессии модулей, принимаешь результат.

Репозиторий: `https://github.com/tnizhnikovskyi-todo/todo_timur`.

## Что ты читаешь

- `factory3d/build/BUILD_STATUS.md` — единственный источник состояния. Правишь его только ты.
- Отчёты лидеров — первые 15 строк `factory3d/build/modules/<m>.md` в их ветке.
- Документацию модулей сам **не** читаешь — это работа лидеров. Граф зависимостей уже перенесён в BUILD_STATUS.
- Держи свой контекст маленьким: без длинных выводов, без чтения кода. Любая работа с кодом — агенту `coder`.

## Продолжение после очистки контекста

Всё состояние — в BUILD_STATUS, отчётах модулей и ветках; история чата не нужна. Если ты не помнишь, что
делал раньше, — прочитай BUILD_STATUS: при «Шаг 0: готов» сразу переходи к циклу, начиная с проверки
модулей `IN_PROGRESS` (шаг 2, без ожидания). Незакоммиченные изменения в рабочей копии — сначала `git status`.

## Шаг 0 — один раз (пропусти, если в BUILD_STATUS «Шаг 0: готов»)

1. Создай ветку интеграции `claude/factory3d-build` от текущего коммита и запушь. Документация
   замораживается на этом коммите; в BUILD_STATUS запиши его хэш.
2. Агенту `coder`: портировать скрипты среды из `smartgen/tools/odoo/` ветки
   `claude/dreamy-ramanujan-p2wlej` (`git fetch origin claude/dreamy-ramanujan-p2wlej`, файлы читать через
   `git show origin/claude/dreamy-ramanujan-p2wlej:smartgen/tools/odoo/<файл>`; там же `ENV.md` с описанием)
   в `factory3d/tools/odoo/` под **Odoo 19**:
   - исходники Odoo `19.0`, addons-path `<odoo>/addons,<корень worktree>/factory3d/odoo_addons`;
   - шаблонная база `f3d_template` со стандартными зависимостями модулей из BUILD_STATUS («Среда»);
   - `run_tests.sh <db> [test-tags]` с переменной `F3D_TEST_INSTALL` (какие модули ставить через `-i`),
     печатает только итог, ошибки с трейсбеками и хвост лога; блокировки и порт — по имени базы;
   - `setup.sh` идемпотентный: в свежем контейнере поднимает всё одной командой.
   Готово, когда `run_tests.sh f3d_smoke` ставит модуль-заглушку на шаблон (заглушку потом удалить),
   скрипты закоммичены в `claude/factory3d-build`.
3. Агенту `coder`: проверить, какие стандартные модули из колонки «Зависимости Odoo» ставятся в этой среде
   (Enterprise-модули, например `mrp_workorder`, `web_gantt`, в Community недоступны). Результат —
   в BUILD_STATUS, раздел «Среда». Модули, чьи зависимости недоступны, получают статус `BLOCKED-ENV`;
   один раз напиши об этом в чат (⛔, какие зависимости и что нужно от человека) и работай с остальными.
4. В BUILD_STATUS: «Шаг 0: готов». Переходи к циклу.

## Цикл

1. **Запуск.** Выбери модули со статусом `TODO`, у которых все модули из колонки «Зависит от» — `DONE`.
   Приоритет: порядок в таблице (эмулятор и телеметрия раньше — от них зависят стендовые тесты остальных).
   Ограничения из раздела «Темп». Для каждого:
   `create_session` с параметрами `source_url` — репозиторий, `source_revision` — `claude/factory3d-build`,
   `outcome_branch` — `claude/f3d-<m>`, `title` — `f3d: <m>`, `permission_mode` не указывать
   (никогда не `plan`), `model` не указывать, `prompt`:
   «Ты лидер модуля <m>. Твоя ветка — claude/f3d-<m>. Следуй factory3d/build/MODULE_LEAD.md.»
   В BUILD_STATUS: статус `IN_PROGRESS`, id сессии, время старта. Закоммить и запушь BUILD_STATUS.
2. **Проверка.** Поставь `send_later` на 60 минут с сообщением
   «Проверка factory3d: продолжай по factory3d/build/MANAGER.md, раздел «Цикл»».
   Перед этим `list_triggers`: если такая проверка уже запланирована и ещё не сработала — вторую не ставь.
   При пробуждении для каждого модуля `IN_PROGRESS`:
   - `git fetch origin claude/f3d-<m>` и `git show origin/claude/f3d-<m>:factory3d/build/modules/<m>.md | head -15`;
   - `get_session`; `list_events` — только при необходимости, `kinds=["result"]`, последние 3.
3. **Разбор.**
   - Отчёт `Статус: DONE` → агенту `coder`: смержить `claude/f3d-<m>` в `claude/factory3d-build`,
     прогнать тесты всех `DONE`-модулей вместе с этим (`F3D_TEST_INSTALL=<список> run_tests.sh f3d_int f3d`),
     запушить. Зелёно → статус `DONE`, итог тестов, число DEC; сообщение ✅ в чат.
     Красно → откатить мерж (не пушить), `send_message` лидеру с итогом теста (≤20 строк).
   - Сессия упёрлась в лимит использования → `send_later` на время сброса +10 минут, затем
     `send_message` лидеру: «Продолжай по MODULE_LEAD.md с первого незавершённого воркера.» Сообщение ⏸ в чат.
   - Сессия завершилась или простаивает без `DONE`, отчёт `BLOCKED*` → прочитай причину (head -15).
     Причина устранима (твоё решение, недостающий мерж) → один `send_message` с решением.
     Нет или повторилось → статус `BLOCKED`, сообщение ⛔ в чат, переходи к независимым модулям.
   - Сессия упала (status_bucket `failed`) → один раз `send_message` «Продолжай по MODULE_LEAD.md»;
     второе падение → `BLOCKED`.
4. После разбора обнови BUILD_STATUS, закоммить и запушь, вернись к шагу 1.
5. Все модули `DONE`/`BLOCKED*` → итоговое сообщение в чат, `send_later` больше не ставь.

## Темп (бережём недельный лимит)

- Одновременно не больше **2** сессий модулей.
- Не больше **2** новых сессий модулей за 24 часа.
- Если лидер сообщил, что модуль упирался в лимит больше одного раза, — снизь до 1 сессии одновременно
  и напиши об этом в чат.

## Сообщения в чат — только эти, по 2–4 строки

- `✅ <модуль> готов — ветка claude/f3d-<m> смержена, тесты N/N, решений без заказчика: K (factory3d/build/modules/<m>.md)`
- `⛔ <модуль> заблокирован — причина; что нужно от человека`
- `⏸ пауза до <время> — лимит`
- Итог по завершении всех модулей.

Пробуждение без изменений — в чат ничего не пиши, просто поставь следующий `send_later`.
