# Чек-лист приёмки кода модулей Odoo 19

Применяет лидер модуля при приёмке воркера, дополнительно к тесту и `git diff --stat`: проходит по пунктам,
относящимся к изменённым файлам, и при сомнении смотрит точечный diff (`| head -80`). Конвенции проекта —
`factory3d/docs/ARCHITECTURE.md` §5; здесь — только то, что тесты обычно не ловят.
Составлено своими словами по идеям из внешних источников (см. `factory3d/tools/external/README.md`).

## 0. Автоматически

- `factory3d/tools/external/lens.sh factory3d/odoo_addons/<m>` — ошибок нет. Ошибки в файлах воркера
  возвращаются тому же воркеру вместе с выводом линтера.

## 1. Синтаксис, изменившийся в Odoo 17–19

- SQL-ограничения и индексы — атрибутами `models.Constraint(...)` / `models.Index(...)`, не `_sql_constraints`.
- Группы — через `privilege_id` (`res.groups.privilege`); `category_id` у `res.groups` больше нет.
- Представления — `<list>`, не `<tree>`; видимость и обязательность — выражения `invisible`/`readonly`/
  `required`, не `attrs` и не `states`.
- QWeb — `t-out`, не `t-esc`.
- Агрегаты — `_read_group()` / `formatted_read_group()`, не `read_group()`.

## 2. ORM и производительность

- Нет `search`/`browse`/`create`/`write` внутри цикла по записям без явной причины; создание — пачкой
  `create([...])`.
- `@api.depends` перечисляет все поля, включая пути через точку; хранимые вычисляемые поля — осознанно.
- Ошибки — `UserError`/`ValidationError`/`AccessError`, не `Exception` и не `assert`.
- Нет `self.env.cr.commit()` в бизнес-методах; операции, которые могут оборвать транзакцию
  (вставка с уникальным ключом из телеметрии), — в `with self.env.cr.savepoint():`.

## 3. Права и границы доверия

- У каждой новой хранимой модели есть строки в `ir.model.access.csv` для групп из §5.
- `sudo()` — только на явной границе (контроллер колектора, крон) и не возвращает лишние записи наружу.
- Контроллеры: правильный `auth`, метод, `csrf`; токен сверяется через `hmac.compare_digest`,
  в лог не пишется; вход валидируется до записи в базу.
- Мультикомпания: домены и правила записей не пропускают чужие компании.

## 4. Данные, манифест, хуки

- `depends` манифеста покрывает все унаследованные модели, XML-ссылки и ассеты.
- Порядок `data`: группы → `ir.model.access.csv` → правила → данные → представления → действия → меню.
- Справочные данные — `noupdate="1"`; демо — только в `demo`.
- `uninstall_hook` не удаляет бизнес-данные; стоп-краны `read_enabled`/`write_enabled` на месте.

## 5. Тесты

- Каждый новый `test_*.py` импортирован в `tests/__init__.py`, класс с тегами `post_install`, `-at_install`, `f3d`.
- Права проверены под реальным пользователем (`with_user`), а не только под суперпользователем.
- Внешние вызовы (колектор, устройства) замоканы на границе, проверено и состояние, и вызов мока.
