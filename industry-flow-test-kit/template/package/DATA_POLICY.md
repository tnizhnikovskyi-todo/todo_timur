# DATA_POLICY пакета mebli — тест, затверджено для тесту

## Дозволено передавати в AI
Тест етапу 1 — галузеве дослідження, **даних клієнтів немає**. Клас даних кроків: `none` (A-01, A-20, A-21) і `commercial` (A-05, A-23: відкритий реєстр юросіб); A-03 — `none` (відкриті джерела).
Дозволено: агрегати й ЄДРПОУ з `odb-catalog` (відкритий реєстр), відкриті веб-джерела, власні матеріали Власника продукту про галузь.
Ніколи: ПІБ, контакти, паролі, реквізити, прод-дані, дані баз клієнтів. Базу Odoo в тесті не підключаємо (`odoo_connections: []`).
Виняток A-04: наряд має `client_data: personal` і `executor: central` — вимога Кроку 0 скіла; дані проєктів читаються лише після рішення людини про підставу обробки (питання не закрите). Виняток для A-04 (потрібен лише якщо Власник продукту сам вирішить його перевіряти): читання лише звітів AIKB у режимі «лише звіти»; Fathom — не дозволено. Відкрите питання до людини: чи входить A-04 у цей тест із реальними проєктами.

## Місця зберігання
Репозиторій цього тесту (git), локальна робоча тека `docs/industries/mebli/_input/` — поза git (`.gitignore`). Odoo `flow` у тесті немає. Drive: не використовується (файл адрес A-23 `адреси` не формується, розсилки немає).
Відкрите питання (Юрист): тека Drive для файлу адрес — у тесті не визначена; режим `адреси` не запускати.
