# Стенд «Генератори» (td_genset) в Docker

Локальный стенд модуля Odoo 18 «Генератори» (`smartgen/td_genset`) с эмулятором ретранслятора SmartGen. После
одной команды в браузере открывается карточка генератора «Стенд» с живыми данными: пульт, события, тревоги,
аналитика, расписание. Сценарии (пропала сеть, связь, топливо…) включаются запросом к эмулятору. Настоящий
генератор и настоящий ретранслятор стенд не трогает.

| Контейнер | Образ | Что делает |
|---|---|---|
| `db` | `postgres:16` | база данных Odoo (том `db-data`) |
| `relay` | `python:3.12-slim` | эмулятор ретранслятора `smartgen/tools/fake_relay.py`: генератор HGM6120N, сеть, топливо, АКБ, команды; API как у ретранслятора 1.1.1, снимок раз в 10 с; порт 8081 |
| `odoo` | `odoo:18.0` | Odoo 18 с модулем; при первом старте ставит модуль и настраивает стенд; порт 8069 |

## Что нужно

- **Docker Desktop** (Windows 10/11 с WSL 2, macOS на Intel или Apple Silicon, Linux), запущенный. Проверка:
  `docker compose version` → `v2…` или новее. На Linux подойдёт и Docker Engine с плагином Compose v2.
- Docker Desktop → Settings → Resources → Memory: **не меньше 4 ГБ**; на диске ~5 ГБ (образы ≈ 1,5 ГБ + данные).
- Свободные порты **8069** (Odoo) и **8081** (эмулятор). Порт **5432** не нужен: Postgres наружу не открыт
  (если нужен доступ к базе с компьютера — см. комментарий у `db` в `docker-compose.yml`, тогда 5432 должен быть свободен).
- Git и доступ к репозиторию (или ZIP ветки с GitHub); интернет при первом запуске — скачать образы.

Порты открыты только на `127.0.0.1`: с других компьютеров сети стенд не виден. Пароли и токен — учебные.

## Запуск

```bash
git clone -b claude/dreamy-ramanujan-p2wlej https://github.com/tnizhnikovskyi-todo/todo_timur.git
cd todo_timur/smartgen/docker
docker compose up -d
```

На Windows команды те же (PowerShell, Git Bash или терминал Docker Desktop). Клонируйте в папку пользователя —
Docker Desktop по умолчанию даёт контейнерам доступ к ней.

**Сколько ждать.** Первый запуск: загрузка образов (≈ 1,5 ГБ, 2–10 мин в зависимости от интернета) плюс установка
модуля и настройка стенда (обычно 3–5 мин). Следующие запуски — 10–20 с.

**Как следить:**

```bash
docker compose logs -f odoo   # лог установки и работы Odoo; Ctrl+C — выйти из лога (стенд продолжает работать)
docker compose ps             # db, relay, odoo — running; odoo станет (healthy) после установки
```

В логе по порядку: `[stand] база genset: missing` → `[stand] Первый старт: установка…` → строки установки →
`[seed] …` (что настроено) → `[stand] Запуск Odoo…` → `HTTP service (werkzeug) running on …:8069` и
`Modules loaded.` Стенд готов, когда http://localhost:8069 показывает страницу входа.

## Вход

http://localhost:8069 — интерфейс на украинском, часовой пояс Europe/Kyiv.

| Логин / пароль | Роль в модуле | Что может |
|---|---|---|
| `admin` / `admin` | системный администратор и «Тех. адміністратор» | всё, включая настройки Odoo |
| `qa_s` / `qa_s` | Генератори: Співробітник | смотрит, таймер «Робота поза графіком», принимает тревоги (ланцюжок, рівень 1) |
| `qa_a` / `qa_a` | Генератори: Адміністратор | + розклад, дні-винятки, паливо; відповідальний за «Стенд» (рівень 2) |
| `qa_t` / `qa_t` | Генератори: Тех. адміністратор | + пульт, автомати, ТО, налаштування модуля (рівень 3) |

Вторую роль удобно открыть в окне инкогнито или другом браузере: изменения видны в обоих окнах без F5.

Что настроено автоматически (`seed.py`, один раз при первом старте): адрес ретранслятора `http://relay:8081/api/v1`
и токен эмулятора; генератор «Стенд» (HGM6120N, 30 kW, бак 145 L), «Опитувати ретранслятор» и «Дозволити команди»
включены — это эмулятор; розклад пн–пт 08:45–18:30; ланцюжок ескалації `qa_s` (0 хв) → `qa_a` (10 хв) → `qa_t`
(30 хв); уведомления — во «Входящие» Odoo (почты на стенде нет); валюта компании — UAH.

## Что вы увидите

**Генератори → Генератор** — карточка «Стенд». Примерно через минуту после старта Odoo (задача «Генератори: забір
показань і стан» работает раз в минуту) в шапке — «Онлайн · N с тому», режим «Авто», стан «Очікування», мережа є,
паливо 95 % (≈ 138 L), АКБ 27,8 V, мотогодини 34 год 51 хв, 39 пусків, 253 kWh. Эмулятор делает снимок раз в 10 с,
Odoo забирает их раз в минуту, карточка обновляется сама.

Забрать данные сразу:

- кнопка **«Оновити дані»** в шапке карточки — данные через несколько секунд;
- или режим разработчика http://localhost:8069/odoo?debug=1 → **Налаштування → Технічні налаштування →
  Автоматизація → Заплановані дії** → «Генератори: забір показань і стан» → **«Виконати вручну»**.

Сразу после первого забора появятся тревога-предупреждение «Термін ТО: перше 30 год…» и заявка «ТО-1 після обкатки
(30 мотогодин)». Так и должно быть: у эмулятора 34 мотогодини, а первое ТО — на 30. Закрыть: `qa_t` или `admin` →
смарт-кнопка «До ТО, мотогодин» на карточке → заявка → стадия «Відремонтовано»; следующее ТО — через 250 мотогодин.

Ещё: **Показання** (журнал 15 хв), **Події**, **Аналітика**, **Заправка**; на карточке — смарт-кнопки «Тривоги» и
«Команди», «Наступна подія» розкладу. В будни в 08:45 Odoo отправляет генератору «Авто», в 18:30 — «Ручний» + «Стоп»
(видно в «Команди»). Сразу после старта стенда команд нет: расписание срабатывает только на переходах.

## Сценарии через эмулятор

Эмулятор управляется запросом `POST http://localhost:8081/_sim` с JSON. С компьютера нужен заголовок с токеном
эмулятора — без него ответ `401` (без токена `/_sim` принимает запросы только изнутри контейнера `relay`).

macOS / Linux / Git Bash / WSL:

```bash
curl -s -X POST http://localhost:8081/_sim -H "Authorization: Bearer dev-token-0123456789abcdefghij" \
     -H 'Content-Type: application/json' -d '{"mains_normal": false}' -o /dev/null -w '%{http_code}\n'
```

Короче — функция на время сессии терминала (ответ `200` — принято):

```bash
sim() { curl -s -X POST http://localhost:8081/_sim -H "Authorization: Bearer dev-token-0123456789abcdefghij" -H 'Content-Type: application/json' -d "$1" -o /dev/null -w '%{http_code}\n'; }
sim '{"mains_normal": false}'
```

Windows PowerShell (`curl` там — другая команда, используйте `Invoke-RestMethod`):

```powershell
function sim($json) { Invoke-RestMethod -Method Post -Uri http://localhost:8081/_sim -Headers @{ Authorization = 'Bearer dev-token-0123456789abcdefghij' } -ContentType 'application/json' -Body $json | Out-Null; 'OK' }
sim '{"mains_normal": false}'
```

Windows cmd: `curl.exe -s -X POST http://localhost:8081/_sim -H "Authorization: Bearer dev-token-0123456789abcdefghij" -H "Content-Type: application/json" -d "{\"mains_normal\": false}"`.

Состояние эмулятора (режим, стан, топливо, связь):

```bash
curl -s http://localhost:8081/_sim -H "Authorization: Bearer dev-token-0123456789abcdefghij"
```

```powershell
Invoke-RestMethod http://localhost:8081/_sim -Headers @{ Authorization = 'Bearer dev-token-0123456789abcdefghij' }
```

После запроса нажмите «Оновити дані» на карточке или подождите до минуты.

| Запрос | Что происходит | Что видно в Odoo |
|---|---|---|
| `{"mains_normal": false}` | пропала сеть; в режиме «Авто» через ~5 с пуск, через ~45 с генератор под нагрузкой | «Мережа: немає», етап «Пуск» → «Робота», живлення від генератора; події «Відключення мережі» и «Робота генератора»; в чатере «Зникла мережа о …», «Генератор запущено о …: Зникла мережа · режим Авто» |
| `{"mains_normal": true}` | сеть вернулась; через ~5 с охлаждение и останов (~45 с) | «Мережа повернулася: Генератор підхопив за N с (без мережі …)», «Генератор зупинено о …: Пуск з 1-ї спроби, навантаження прийнято; мережа повернулася» |
| `{"link": false}` | модуль связи пропал, снимков нет | через 3 мин без данных — «Немає зв'язку», событие «Зв'язок»; ещё через 10 мин — критическая тревога «Немає зв'язку з модулем», уведомление `qa_s`, затем эскалация на `qa_a` (+10 хв) и `qa_t` (+30 хв), если никто не нажал «Прийняв» |
| `{"link": true}` | связь вернулась | в течение минуты «Онлайн», в чатере «Зв'язок відновлено після N хв без даних.», тревога снята |
| `{"link": false, "advance": 600}` | часы эмулятора «перемотаны» на 10 мин вперёд без связи: «модуль молчит уже 10 минут» | «Немає зв'язку» — при следующем заборе, критическая тревога — ещё примерно через 3 мин. Вернуть: `{"link": true, "clock_offset": 0}` (связь и часы эмулятора) |
| `{"fuel_level": 40}` | уровень в баке 95 → 40 % (≈ 138 → 58 L), двигатель стоит | событие «Падіння рівня палива», критическая тревога «Рівень палива впав на 80 L без роботи двигуна» (висит, пока не нажмут «Прийняв») |
| `{"fuel_level": 15}` | меньше 20 % бака | тревоги «Низький рівень палива: 22 L» и «Попередження: низький рівень палива» (сигнал контроллера), задача «Долити паливо» |
| `{"fuel_level": 95}` | долили | событие «Заправка», в чатере «Рівень палива зріс: +… L (… → 138 L)», тревоги о низком уровне сняты |
| `{"no_exec": true}` | контроллер принимает команды, но не выполняет | нажмите на пульте (`admin` / `qa_t`) «Ручний»: в «Команди» — «Надіслано», повторы каждые 2 мин, через 10 мин «Не підтверджено» и критическая тревога «Команда «Ручний» не підтверджена…». Вернуть: `{"no_exec": false}`; команда, которая ещё повторяется, тогда выполнится — режим вернуть пультом «Авто» |
| `{"cloud_press": "manual"}` | кто-то нажал «Ручний» в приложении SmartGen, не в Odoo | режим «Ручний», «Керує: Не з Odoo», событие «Керування не з Odoo» и тревога-предупреждение. Вернуть: пульт «Авто» (`admin` / `qa_t`) — режим сменится за секунды, в «Команди» через минуту «Підтверджено» |
| `{"reset": true}` | эмулятор в исходное состояние: Авто, сеть и связь есть, топливо 95 %, флаги сняты | Odoo видит это как обычные изменения (например, «Заправка», если топливо было ниже; «Керування не з Odoo», если режим был другим). Нумерация снимков продолжается — данные поступают дальше. Журнал команд эмулятора тоже очищается: не делайте reset, пока команда пульта ещё «Надіслано» |

Особенности:

- В будни после 18:30 расписание переводит генератор в «Ручний» + «Стоп», и при пропаже сети он не запустится — как
  на объекте (событие закроется «Генератор не запускався — поза розкладом»). Вернуть «Авто» — кнопкой пульта
  (`admin` / `qa_t`).
- Тихі години 22:00–07:00: предупреждения в это время только записываются в чатер, без уведомлений; критические —
  всегда с уведомлением.
- `advance` при включённой связи даёт снимки «из будущего» (часы эмулятора уходят вперёд). Если так вышло —
  `{"clock_offset": 0}`.
- Все ключи `/_sim` (ускорение физики `time_scale`, отказы `fail_next`, подмена значений `set` и др.) — в начале
  файла `smartgen/tools/fake_relay.py`.

## Остановить, перезапустить, сбросить

```bash
docker compose stop            # остановить; данные сохраняются (docker compose start — продолжить)
docker compose up -d           # запустить снова (и после правки docker-compose.yml)
docker compose restart relay   # перезапуск эмулятора: сценарии сброшены, данные в Odoo идут дальше
docker compose down            # удалить контейнеры; база и файлы Odoo остаются в томах
docker compose down -v         # удалить всё, включая базу; следующий up -d поставит стенд заново (3–5 мин)
```

Пока стенд не остановлен командой `docker compose stop`, контейнеры запускаются сами вместе с Docker Desktop
(политика `restart: unless-stopped`).

Обновить модуль после `git pull`: проще всего пересоздать стенд — `docker compose down -v && docker compose up -d`.
С сохранением данных:

```bash
docker compose stop odoo
docker compose run --rm --entrypoint odoo odoo -c /etc/odoo/odoo.conf -d genset -u td_genset --stop-after-init
docker compose start odoo
```

Повторить настройку стенда (вернёт адрес эмулятора, пароли и роли qa_*, включит опрос и команды «Стенда»; ничего
не дублирует): `docker compose exec odoo bash -c "odoo shell -c /etc/odoo/odoo.conf -d genset < /opt/stand/seed.py"`.

Копия или восстановление базы стенда: менеджер баз http://localhost:8069/web/database/manager, мастер-пароль `stand`.

## Переключить стенд на настоящий ретранслятор (только чтение)

> **Внимание.** Настоящий ретранслятор управляет **реальным генератором** в офисе. На стенде — только чтение:
> никогда не включайте «Дозволити команди» у генератора, который опрашивает настоящий ретранслятор, и не создавайте
> ему расписание.

Адрес и токен настоящего ретранслятора выдаёт ToDo — в репозитории их нет.

1. `admin` → **Генератори → Налаштування → Генератори** → «Стенд»: выключить «Дозволити команди» и «Опитувати
   ретранслятор» → Зберегти.
2. **Налаштування → Генератори**: «Адреса API ретранслятора» — `https://<адрес ретранслятора>/api/v1`, «Токен
   ретранслятора» → Зберегти.
3. **Генератори → Налаштування → Генератори → Створити**: назва (например «Садова — реальний»), модель контролера
   HGM6120N, потужність, бак 145 L, «ID модуля (hostid)» настоящего модуля, «Опитувати ретранслятор» — включить,
   «Дозволити команди» — **оставить выключенным** → Зберегти → «Перевірити зв'язок».
4. Первый забор догоняет историю за 30 дней («Починати історію з») — около 10 минут; в чатере появится
   «Догнано історію: …».

Почему отдельная карточка: у «Стенда» hostid только для стенда (`5354414E442D444F434B4552`). Настоящий ретранслятор
такой не знает (ответ 404), поэтому команды «Стенда» до реального генератора не дойдут; история «Стенда» относится
к эмулятору.

Вернуться на эмулятор: на реальной карточке выключить «Опитувати ретранслятор»; в Налаштування → Генератори —
адрес `http://relay:8081/api/v1` и токен `dev-token-0123456789abcdefghij`; на «Стенде» снова включить опрос и
команды. Или полный сброс: `docker compose down -v && docker compose up -d`.

## Типовые проблемы

| Симптом | Что делать |
|---|---|
| `port is already allocated` / `address already in use` (8069 или 8081) | Порт занят другой программой (часто — локальный Odoo). Найти: macOS/Linux `lsof -nP -iTCP:8069 -sTCP:LISTEN`, Windows `netstat -ano \| findstr :8069`. Остановить её или в `docker-compose.yml` поменять левую часть: `"127.0.0.1:18069:8069"` → http://localhost:18069 (для 8081 — так же, и новый порт в запросах `/_sim`); затем `docker compose up -d` |
| Apple Silicon: `no matching manifest for linux/arm64/v8` | Образы многоархитектурные, обычно этого нет. Если есть — раскомментировать `platform: linux/amd64` у `odoo` в `docker-compose.yml` (заработает через эмуляцию, медленнее) |
| Windows: в логе odoo `$'\r': command not found` или `invalid option name` | В `entrypoint.sh` переводы строк CRLF. В папке есть `.gitattributes` (`*.sh text eol=lf`), поэтому достаточно пересоздать файл из git: `rm entrypoint.sh` (PowerShell: `Remove-Item entrypoint.sh`), `git checkout -- entrypoint.sh`, затем `docker compose up -d --force-recreate odoo` |
| Образ не скачивается (`TLS handshake timeout`, `toomanyrequests`, `pull access denied`) | Проверить интернет и прокси (Docker Desktop → Settings → Resources → Proxies), выполнить `docker login`, повторить `docker compose pull` и `docker compose up -d` |
| `Mounts denied` / `path … is not shared` | Клонировать в папку пользователя или добавить путь: Docker Desktop → Settings → Resources → File sharing |
| Odoo перезапускается по кругу | `docker compose logs --tail=200 odoo` — найти Traceback. Если прервалась первая установка (выключили компьютер, не хватило памяти) — `docker compose down -v && docker compose up -d` |
| Страница не открывается дольше 15 мин | `docker compose ps` и `docker compose logs odoo`; памяти Docker Desktop — не меньше 4 ГБ |
| На карточке нет данных | `docker compose ps` — `relay` работает? В `docker compose logs relay` раз в минуту запросы Odoo `GET /api/v1/status`. На карточке (`admin` / `qa_t`) — «Перевірити зв'язок»; в Налаштування → Генератори адрес `http://relay:8081/api/v1` |
| `/_sim` отвечает `401` | Нет заголовка `Authorization: Bearer dev-token-0123456789abcdefghij` |
| Linux: `Permission denied` к файлам модуля | Файлы должны читаться всеми: `chmod -R a+rX smartgen` (если umask 077); при SELinux — добавить `:z` к томам в `docker-compose.yml` |

## Файлы папки

| Файл | Назначение |
|---|---|
| `docker-compose.yml` | сервисы `db`, `relay`, `odoo`; тома `db-data`, `odoo-data`; порты 127.0.0.1:8069 и 127.0.0.1:8081 |
