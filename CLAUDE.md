# CLAUDE.md

## Репозиторий (эта ветка)

- `warehouse3d/` — конструктор склада (локации и размещение Odoo). План и состояние: `warehouse3d/build/`.
- `luxsite/`, `odoo_graph/` — отдельные проекты, к конструктору не относятся.
- Пример организации больших сборок — ветка `claude/factory3d-build` (`factory3d/build/MANAGER.md`).

## Бюджет: правила экономии лимита

Расход ≈ размер контекста × число обращений к модели. Каждый вызов инструмента перечитывает весь контекст.
Держи контекст коротким, а шагов мало; состояние храни в файлах, а не в истории чата.

- Сначала Grep, потом Read нужного диапазона строк. Файл до ~200 строк можно читать целиком.
- Не перечитывать неизменённый файл. Не читать файл «для проверки» после Edit.
- Вывод команд всегда ограничивать: `| tail -30`, `| head -60`, `grep -E "FAIL|ERROR|Traceback" -A 15`.
- Прототип `sklad.html` содержит встроенный JSON на сотни KB — никогда не выводить его и не читать целиком.
- Независимые Read/Grep — параллельно в одном ходе.
- Веб-поиск — только если ответа нет в репозитории. Документацию Odoo — WebFetch с конкретным вопросом.
- Браузерная проверка — Playwright-скрипт с кратким текстовым итогом; скриншот только для проверки визуала.

## Роли

- Менеджер проекта (Opus) — план, постановка задач, приёмка, `warehouse3d/build/STATUS.md`. Код сам не пишет.
- `coder` (Sonnet) — реализация, тесты, рефакторинг, git-операции. Всё, что больше ~30 строк или 2 файлов.
- `scout` (Haiku) — поиск по коду и документации Odoo, только чтение.
- Задача агенту самодостаточна: цель и критерий готовности; файлы, которые можно менять; пункты плана (W-xx, D-xx),
  которые читать; команда проверки; ответ ≤15 строк без кода и диффов.
- Параллельно — только независимые задачи, не больше 3 агентов. Неудачный результат — уточнение тому же агенту
  (SendMessage), а не новый агент.
- Приёмка — тестом и `git diff --stat`, а не перечитыванием изменённых файлов.
